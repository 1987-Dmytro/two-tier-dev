# INTENT — two-tier-dev (система разработки «оператор · тимлид · исполнитель»)

**Владелец:** Дмитрий (оператор). **Текст ведёт:** тимлид, по словам оператора. **Подпись:** 09.10.2026, «согласен со всеми твоими предложениями полностью» (грилинг v3.2). **Прежний intent:** `intent/two-tier-dev-v2.md` (18.09) — история.

## Проблема
v2 лечил разрастание, и за 17 дней болезнь вернулась: скилл `team-lead` вырос в 7 раз, процессных документов стало впятеро больше кода, приёмка шла дольше плеча, харнес отстал от модели. v3 и v3.1 закрыли это механикой. Осталась дыра между «сказал» и «сделал»: конец хода судили по словам исполнителя, а проверка по файлам приходила на приёмке через часы. `/goal`, по оценке оператора, мешает разработке: фазу должна вести правильная спека.

## Желаемый результат
Оператор ведёт любой свой проект циклом intent → прожарка → SPEC → запуск фазы → приёмка → гейт.
- Исполнитель получает результат, проверку, границы и стопы, а путь строит сам.
- Фазу ведёт спека: конец хода держит `spec-gate` по файлам evidence, а не по словам; `/goal` в цикле нет.
- Объём инструкций держит механика, а не память.
- Intent живой и закреплён в SPEC пином.
- Система улучшает себя только по официальным источникам Anthropic.
- Новый проект разворачивается одной командой (`bin/two-tier-init`), живой переводится одной командой (`bin/two-tier-upgrade`) без потери истории.

## Сигналы успеха
- **S1** — `bin/check-budget` зелёный на ките и в каждом проекте; CI на push зелёный.
- **S2** — обязательное чтение исполнителя на старте — не больше 50 тыс. знаков: `Read first:` стартового запроса фазы (до 3 файлов) плюс автозагружаемый CLAUDE.md; auto memory в ките выключен.
- **S3** — на фазу: стопов, кроме ожидания внешних входов, не больше трёх; блокирующих находок на приёмку — не больше пяти; приёмка тимлида не дольше плеча исполнителя.
- **S4** — коммитов с правкой продукта не меньше, чем коммитов по ревью.
- **S5** — каждая правка скилла или харнеса — в CHANGELOG со ссылкой на официальный источник (или на повтор не меньше двух раз) и с итогом контрольного прогона.
- **S6** — живой проект переведён без потери истории (архив плюс ветка) и продолжает фазу.
- **S7** — фаза не кончается словом «готово» без маркера каждой фичи: такой конец хода блокируется и называет недостающее; ложных блоков — не больше одного на плечо.

## Жёсткие ограничения
- **C1** — ничего не удаляется: история уходит в `docs/archive/` через `git mv`; `main` меняется только после приёмки.
- **C2** — харнес — только по документации (Claude Code — официальной; стороннего инструмента — его собственной); каждое поле — с контрольным прогоном.
- **C3** — платное — только Jev в потолке PROCESS §Деньги; остальное — подписка. Сеть — github.com, официальная документация, api.typesafe.ai.
- **C4** — живой проект не трогается, пока кит не принят; перевод — на отдельной ветке.
- **C5** — скиллы Cowork сохраняет оператор из карточек; репо хранит их копию.
- **C6** — хуки и скрипты с Jev не читают реальные персональные данные; ключ — только в окружении, не в репо.

## Не-цели
- **N1** — не меняем состав моделей ради моды.
- **N2** — не строим своего оркестратора поверх Claude Code: воркфлоу ultracode — штатный режим, `spec-gate` — Stop-хук, а не цикл.
- **N3** — не переписываем роли брифа.

## Решено и открыто

- **D2** (06.10) — исполнитель в auto mode; доверенная инфраструктура — в `--settings`.
- **D3** (06.10) — intent — один живой файл с пином в SPEC и журналом разворотов.
- **D4** (07.10) — исполнитель под ultracode; приёмка — `/verify-phase`, 30 мин. Планки лимитов подписки сняты 07.10.
- **D5** (09.10) — `/goal` уходит из кита: фазу запускает стартовый запрос в строке запуска, конец хода держит `spec-gate` (код — по файлам, Jev — на нечётком; кап блоков и времени, при ошибке пропускает).
