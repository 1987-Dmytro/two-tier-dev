# INTENT — two-tier-dev (система разработки «оператор · тимлид · исполнитель»)

**Владелец:** Дмитрий (оператор). **Текст ведёт:** тимлид, по словам оператора. **Подпись:** 06.10.2026, «согласен» (сессия ретро). **Прежний intent:** `intent/two-tier-dev-v2.md` (18.09) — история.

## Проблема
v2 лечил разрастание: «скилл вырос до 385 строк, оператор стал шиной, интеллект тратился на рулинги вместо решений». За 17 дней болезнь вернулась. Скилл `team-lead` вырос с 4,8 до 34,3 тыс. знаков. В фазе 1 telefon-assistent — около 670 тыс. знаков процессных документов против примерно 127 тыс. кода. На старте сессии исполнитель обязан прочитать около 633 тыс. знаков. По ревью — 142 поправки; приёмка шла дольше плеча; был ложный стоп на центовом потолке. Харнес отстал от модели (Opus 5 → 5.5 через алиас), исполнитель работает в bypass на хост-машине. Intent проекта устарел после трёх разворотов: развороты жили в поправках SPEC и ревью-файлах. Двигатель роста — правило «на каждом стопе — правка скилла».

## Желаемый результат
Оператор ведёт любой свой проект циклом intent → прожарка → SPEC → `/goal` → приёмка → гейт.
- Исполнитель получает результат, проверку, границы и стопы, а путь строит сам.
- Объём инструкций держит механика, а не память.
- Intent живой и закреплён в SPEC пином.
- Система улучшает себя только по официальным источникам Anthropic.
- Новый проект разворачивается одной командой (`bin/two-tier-init`), живой переводится одной командой (`bin/two-tier-upgrade`) без потери истории.

## Сигналы успеха
- **S1** — `bin/check-budget` зелёный на ките и в каждом проекте на v3; CI на push зелёный.
- **S2** — обязательное чтение исполнителя на старте — не больше 50 тыс. знаков: `Read first:` в GOAL.txt (до 3 файлов) плюс автозагружаемый CLAUDE.md; auto memory в ките выключен.
- **S3** — на фазу: стопов, кроме ожидания внешних входов, не больше трёх; блокирующих находок на приёмку — не больше пяти; приёмка тимлида не дольше плеча исполнителя.
- **S4** — коммитов с правкой продукта не меньше, чем коммитов по ревью.
- **S5** — каждая правка скилла или харнеса — в CHANGELOG со ссылкой на официальный источник (или на повтор не меньше двух раз) и с итогом абляции.
- **S6** — живой проект переведён на v3 без потери истории (архив плюс ветка) и продолжает фазу.

## Жёсткие ограничения
- **C1** — ничего не удаляется: история уходит в `docs/archive/` через `git mv`; `main` меняется только после приёмки.
- **C2** — харнес — только по официальной документации; каждое поле — с контрольным прогоном.
- **C3** — ничего платного; сеть — github.com и официальная документация.
- **C4** — живой проект не трогается, пока кит не принят; перевод — на отдельной ветке.
- **C5** — скиллы Cowork сохраняет оператор из карточек; репо хранит их копию.

## Не-цели
- **N1** — не меняем состав моделей ради моды.
- **N2** — не строим своего оркестратора поверх Claude Code; agent teams и воркфлоу — только под конкретную задачу.
- **N3** — не переписываем роли брифа в этой фазе: §2а v5.2 переносится в `team-lead-brief` без изменения смысла.
- **N4** — не автоматизируем передачу между сессиями до гейта кита.
