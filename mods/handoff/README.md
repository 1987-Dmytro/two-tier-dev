# handoff — мод Claude Code: хендофф сжатием в той же сессии, без `/clear`

Мод (плагин с функциональными хуками, Claude Code ≥ 2.1.287, Desktop ≥ 2.1.286) для two-tier-dev.

**Что делает (0.5.0).** Хендофф идёт сжатием разговора в этой же сессии — `/clear` мод не делает никогда. `/clear`
(до 0.5.0) терял разговор, список задач и связь с фоновой работой; сжатие оставляет сессию (id, задачи, фоновые задачи,
уведомления) и кладёт сводку на место разговора. Каждое сжатие сессии человека мод ведёт сам:
- **сжатие движка** — его порог посреди хода (`autoCompactWindow`), `/compact` человека, другой плагин: хук `session.compact`
  дописывает в инструкции сводки разделы хендоффа (задача и слова пользователя · список задач · что сделано · решения ·
  текущий и следующий шаг · что идёт в фоне с id/PID и файлами вывода · открытое); текст `/compact <…>` человека идёт первым;
- **порог мода** в конце хода (по умолчанию 70 %, ключ `handoff_threshold_pct` budgets.json сильнее), **Jev-граница**
  (`jev: auto`), кнопка и `/handoff now` — мод сам сжимает сессию между ходами (`$.session.compact` с теми же инструкциями).

После сжатия сводка сохраняется файлом `<handoffDir>/handoff-<YYYY-MM-DD-HHMMSS>-compact-<trigger>.md` — карта на диске;
контекст переносит сама сводка, промпта «прочитай файл» нет: сессия ждёт того же, чего ждала. Строка в
`<handoffDir>/compact.jsonl`: триггер, токены до и после, файл — без текста. Мод сжимает только между ходами (во время хода
сжатие отклоняется), поэтому рост внутри одного хода ограничивает окно сжатия движка: при пороге 40 % окна в 1M —
`autoCompactWindow` ≈ 420000 (движок сжимает на `autoCompactWindow − 20000`, замер кита 12.11: 600000 → 580000).
`/handoff status` печатает эту точку, например `engine compacts at 400k (settings)`.

**Jev-граница (0.3.0, влит Compact Adviser).** Ниже порога, после каждого законченного ответа (не прерванного, не
субагента, заполнение от 10 %) мод одним запросом задаёт Jev два вопроса Compact Adviser 0.1.12: закончена ли
единица работы и делал ли ассистент её сам. Счёт — P(закончено) × (0,5 + 0,5 × P(руками)); планка — 0,90 до 10 %
заполнения и 0,50 на пороге хендоффа, линейно между. Выше планки `jev: hint` подсвечивает полосу («Jev: задача на
границе 0.93 ≥ 0.72»), `jev: auto` сжимает сессию с разделами хендоффа прямо на границе. Ответ, пришедший
после начала следующего хода, отбрасывается. Модель Jev закреплена (`jev-1.13.0`, как в `bin/jev`), таймаут 3 с;
нет `TYPESAFE_API_KEY`, ошибка, таймаут или чужая модель — совета нет, ничего не меняется (`/handoff status`: `key absent`,
последнее решение Jev). Jev получает только
промпт хода и финальный ответ (по 2000 знаков, значение ключа и формы ключей вырезаны) и счёт вызовов инструментов
по имени — ни результатов инструментов, ни содержимого файлов. Каждый вызов — строка в `<handoffDir>/jev.jsonl`:
числа и решение (`hint` · `auto` · `below` · `stale` · `error`), без текста. Сам `compact-adviser` 0.1.12 с Claude Code
2.1.287+ молчит: он включается только при `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`, которую Claude Code больше не читает.

**Вкладка Code (0.4.0, SPEC-v3.5 F1).** `/handoff` регистрируется везде, где мод загружен: хост вкладки стартует как SDK
(`isInteractive` false) и подключает поверхность позже. Сам мод пишет хендофф только в сессии человека — REPL или подключённая
поверхность (`session.attach`, защёлка), как `spec-board` и `window-guard`; в `claude -p` поверхностей нет. Порог — ключ
`handoff_threshold_pct` в `budgets.json` проекта (defaults, проект только ужесточает — правило `window-guard`); нет ключа — опция
`threshold` настроек пользователя, иначе 70. `/handoff status` печатает порог с источником и поверхность:
`threshold 40% (budgets.json) · surface desktop`. До 0.5.0 поле `autoCompactWindow` 600000 профиля было страховкой «сжатие
не срабатывает раньше мода»; с 0.5.0 сжатие движка и есть перенос посреди хода — окно ставят по порогу (выше).

**Кнопки.** Полоса над промптом: `контекст 43% · хендофф @40%  [ Передать → compact ]  [ Только файл ]  Скрыть`.
Горячие клавиши, когда полоса держит фокус (ctrl+x tab): `h` — сжатие с разделами хендоффа, `f` — только файл (вызов
модели над транскриптом, разговор не трогается). После `/clear`, сделанного человеком, полоса возвращается сразу.
При заполнении выше порога строка подсвечивается жёлтым; результат последнего действия показывается рядом.

**Команды.** `/handoff now` — то же, что кнопка · `/handoff write` — только файл и строка свежей сессии
(для нового процесса) · `/handoff status` — заполнение в % и токенах, порог, точка сжатия движка, поверхность, взведён ли,
Jev (режим, ключ есть/нет, последнее решение), последний файл · `/handoff last`.
Строка статуса: `ctx 43% · 427k/1000k · handoff @40%`.

**Где не работает.** `claude -p` и SDK (нет человека у промпта — мод молчит); Cowork (моды там не
исполняются — хендофф тимлида остаётся за скиллом). Агенты воркфлоу и субагенты не трогаются.

**Настройки** (`/config` → handoff, или `pluginConfigs.handoff` в `~/.claude/settings.json` либо в файле `--settings`
строки запуска — так репо тимлида задаёт `handoffDir: "claude"`). `pluginConfigs` в `.claude/settings.json` и
`.claude/settings.local.json` проекта движок не применяет (проба 13.11, движок 2.1.321: там 33 и 34 — статус `70% (option)`,
через `--settings` 35 — `35% (option)`); профиль вкладки Code порог мода не несёт — порог проекта только ключ budgets.json выше:

| поле | по умолчанию | смысл |
|---|---|---|
| `threshold` | 70 | запасной порог: % заполнения окна, после которого мод сам сжимает сессию в конце хода (10–95); `handoff_threshold_pct` budgets.json сильнее |
| `handoffDir` | `handoffs` | каталог относительно корня проекта |
| `autoCompact` | true | на пороге и на Jev-границе — сжатие на месте; `false` — только файл хендоффа. Опция `autoClear` до 0.5.0 снята: `/clear` мод не делает |
| `minTurns` | 2 | не сжимать само раньше N промптов |
| `language` | `ru` | язык документа и инструкций сжатия (`ru` / `en`) |
| `jev` | `hint` | Jev-граница: `off` — не спрашивать, `hint` — подсказка, `auto` — сжатие на границе; в строке запуска исполнителя — `off` |

**Предохранители.** Одно действие за раз; повторно взводится, когда заполнение упало ниже `threshold − 20` — после
сжатия по его размеру `tokensAfter`, а не по устаревшей цифре последнего ответа. Сжатие с порога или Jev не состоялось —
мод занят, вето хука (`skip`, заметка на полосе), отказ во время хода или ошибка (тост «nothing was cleared»): мод
взводится снова и пробует в конце следующего хода; кнопка и `/handoff now` взвод не снимали и не возвращают. Нет цифры
заполнения (ответа ещё не было в этом окне) — решения нет, строка статуса `ctx unknown`. Ходы и сжатия субагентов и
сессии без человека (`claude -p`) мод не трогает.

**Установка из этого репо** (папка `mods/` — локальный marketplace; правка папки → `/reload-plugins`):

```sh
claude plugin marketplace add ~/Desktop/Projects/two-tier-dev/mods
claude plugin install handoff@two-tier-mods --scope user
```

**Проверка.** `claude plugin validate mods/handoff` · `claude plugin test mods/handoff` (36 тестов: регистрация в хосте вкладки, порог budgets.json, поверхность в статусе, авто только при поверхности, второй хендофф и подагент (F1.4), полоса на terminal и desktop, Jev hint · auto (сжатие) · ниже планки · чужая модель · нет ключа · устаревший ответ · off · ниже 10 %; сжатие на пороге без `/clear` и без промпта, `autoCompact: false`, взвод по `tokensAfter` и без него, отказ сжатия во время хода, `/handoff now`, сжатие движка `auto` · `manual` · `precompute` · субагент · без человека, статус; на коде 0.4.0 падают 13 из них) ·
`tsc -p` по tsconfig из заголовка `claude-code.d.ts`.
