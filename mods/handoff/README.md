# handoff — мод Claude Code: хендофф сжатием в той же сессии, без `/clear`

Мод (плагин с функциональными хуками, Claude Code ≥ 2.1.287, Desktop ≥ 2.1.286) для two-tier-dev.

**Что делает (0.6.0).** Хендофф идёт сжатием разговора в этой же сессии — `/clear` мод не делает никогда. `/clear`
(до 0.5.0) терял разговор, список задач и связь с фоновой работой; сжатие оставляет сессию (id, задачи, фоновые задачи,
уведомления) и кладёт сводку на место разговора. Каждое сжатие сессии человека мод ведёт сам:
- **порог мода** — при каждом пересечении порога (40 % в ките: ключ `handoff_threshold_pct` budgets.json, иначе опция
  `threshold`, иначе 70) в конце хода, а также кнопка и `/handoff now`: мод сам сжимает сессию между ходами
  (`$.session.compact` с разделами хендоффа; во вкладке Code движок стартует как SDK и этот вызов отклоняет — «compaction here
  runs inside a turn», — тогда мод запускает команду `/compact` через `$.command.run`, и её сжатие идёт через тот же хук);
- **сжатие движка** — у конца его окна посреди хода (`autoCompactWindow`), `/compact` человека, другой плагин: хук
  `session.compact` дописывает в инструкции сводки те же разделы (задача и слова пользователя · список задач · что сделано ·
  решения · текущий и следующий шаг · что идёт в фоне с id/PID и файлами вывода · открытое); текст `/compact <…>` человека
  идёт первым.

После сжатия сводка сохраняется файлом `<handoffDir>/handoff-<YYYY-MM-DD-HHMMSS>-compact-<trigger>.md` — карта на диске;
контекст переносит сама сводка, промпта «прочитай файл» нет: сессия ждёт того же, чего ждала. Строка в
`<handoffDir>/compact.jsonl`: триггер, токены до и после, файл — без текста. Мод сжимает только между ходами (во время хода
сжатие отклоняется), поэтому рост внутри одного хода ограничивает только сжатие самого движка у конца его окна (замер кита
12.11: при `autoCompactWindow` 600000 `effectiveWindow` 580000) — и оно тоже идёт с разделами хендоффа. Где движок сожмёт,
печатает `/handoff status`: `engine compacts at <N>k (<источник>)`.

**Без Jev и без платных вызовов (0.6.0, слово оператора).** Jev-граница (0.3.0–0.5.0, влит Compact Adviser) снята: мод не
читает `TYPESAFE_API_KEY`, не ходит в сеть и не пишет `jev.jsonl`; код снятой части — `docs/archive/mods-handoff-jev/jev.ts`.
Решение одно — порог по той же цифре, что в приложении. Модель зовёт только «Только файл» / `/handoff write` (`$.model.fork`
над транскриптом сессии — модель самой сессии, не Jev).

**Заполнение — как в приложении.** Процент мод считает от окна сжатия (`rawMaxTokens` разбивки `/context`, оценка
`summary` — без запросов), а не от окна модели: так его показывает приложение. 386k токенов — это 64 % окна сжатия 600k
и только 38 % окна модели 1M; до этой правки мод видел 38 % и не срабатывал на пороге 40 %, пока приложение показывало 64 %.
Разбивки нет — окно модели. Окно сжатия — и знаменатель процента, поэтому уменьшение `autoCompactWindow` не опускает порог
в токенах ниже `порог × окно`.

**Вкладка Code (0.4.0, SPEC-v3.5 F1).** `/handoff` регистрируется везде, где мод загружен: хост вкладки стартует как SDK
(`isInteractive` false) и подключает поверхность позже. Сам мод сжимает только в сессии человека — REPL или подключённая
поверхность (`session.attach`, защёлка), как `spec-board` и `window-guard`; в `claude -p` поверхностей нет. Порог — ключ
`handoff_threshold_pct` в `budgets.json` проекта (defaults, проект только ужесточает — правило `window-guard`); нет ключа — опция
`threshold` настроек пользователя, иначе 70. `/handoff status` печатает порог с источником и поверхность:
`threshold 40% (budgets.json) · … · surface desktop`. До 0.5.0 поле `autoCompactWindow` 600000 профиля было страховкой «сжатие
не срабатывает раньше мода»; с 0.5.0 сжатие движка — перенос посреди хода с разделами хендоффа, а окно — знаменатель
процента (выше).

**Кнопки.** Полоса над промптом: `контекст 64% · хендофф @40%  [ Передать → compact ]  [ Только файл ]  Скрыть`.
Горячие клавиши, когда полоса держит фокус (ctrl+x tab): `h` — сжатие с разделами хендоффа, `f` — только файл (вызов
модели над транскриптом, разговор не трогается). После `/clear`, сделанного человеком, полоса возвращается сразу.
При заполнении выше порога строка подсвечивается жёлтым; результат последнего действия показывается рядом.

**Команды.** `/handoff now` — то же, что кнопка · `/handoff write` — только файл и строка свежей сессии
(для нового процесса) · `/handoff status` — заполнение в % и токенах (от какого окна), порог, точка сжатия движка,
поверхность, взведён ли, последний файл · `/handoff last`.
Строка статуса: `ctx 64% · 386k/600k · handoff @40%` (токены над окном сжатия).

**Где не работает.** `claude -p` и SDK (нет человека у промпта — мод молчит); Cowork (моды там не
исполняются — хендофф тимлида остаётся за скиллом). Агенты воркфлоу и субагенты не трогаются.

**Настройки** (`/config` → handoff, или `pluginConfigs.handoff` в `~/.claude/settings.json` либо в файле `--settings`
строки запуска — так репо тимлида задаёт `handoffDir: "claude"`). `pluginConfigs` в `.claude/settings.json` и
`.claude/settings.local.json` проекта движок не применяет (проба 13.11, движок 2.1.321: там 33 и 34 — статус `70% (option)`,
через `--settings` 35 — `35% (option)`); профиль вкладки Code порог мода не несёт — порог проекта только ключ budgets.json выше:

| поле | по умолчанию | смысл |
|---|---|---|
| `threshold` | 70 | запасной порог: % заполнения окна сжатия (как в приложении), при каждом пересечении которого мод сам сжимает сессию в конце хода (10–95); `handoff_threshold_pct` budgets.json сильнее |
| `handoffDir` | `handoffs` | каталог относительно корня проекта |
| `autoCompact` | true | на пороге — сжатие на месте; `false` — только файл хендоффа. Опции `autoClear` (до 0.5.0) и `jev` (до 0.6.0) сняты |
| `minTurns` | 2 | не сжимать само раньше N промптов |
| `language` | `ru` | язык документа и инструкций сжатия (`ru` / `en`) |

**Предохранители.** Одно действие за раз. Мод взводится всякий раз, когда заполнение ниже порога (после сжатия — по его
размеру `tokensAfter`, а не по устаревшей цифре последнего ответа), поэтому сжимает при каждом пересечении порога; сжатие,
после которого заполнение осталось на пороге или выше, не повторяется каждый ход. Сжатие с порога не состоялось — мод
занят, вето хука (`skip`, заметка на полосе), отказ во время хода или ошибка (тост «nothing was cleared»): мод взводится
снова и пробует в конце следующего хода; кнопка и `/handoff now` взвод не снимали и не возвращают. Нет цифры заполнения
(ответа ещё не было в этом окне) — решения нет, строка статуса `ctx unknown`. Ходы и сжатия субагентов и сессии без
человека (`claude -p`) мод не трогает.

**Установка из этого репо** (папка `mods/` — локальный marketplace; правка папки → `/reload-plugins`):

```sh
claude plugin marketplace add ~/Desktop/Projects/two-tier-dev/mods
claude plugin install handoff@two-tier-mods --scope user
```

**Проверка.** `claude plugin validate mods/handoff` · `claude plugin test mods/handoff` (33 теста: регистрация в хосте
вкладки, порог budgets.json, поверхность в статусе, авто только при поверхности, полоса на terminal и desktop; без Jev — ни
чтения `TYPESAFE_API_KEY`, ни сети; сжатие на пороге без `/clear` и без промпта, каждое пересечение порога и без повтора на
пороге, `autoCompact: false`, взвод по `tokensAfter` и без него, вето, отказ во время хода и отказ кнопки, `/handoff now`,
сжатие движка `auto` · `manual` · `precompute` · субагент · без человека, нет цифры, процент от окна сжатия, статус, ход
субагента) · `tsc -p` по tsconfig из заголовка `claude-code.d.ts`.
