# SPEC-<n> — <проект> — <фаза>

**intent:** `intent/<slug>.md` · **дата:** <дата> · **одна фаза = один SPEC = один `/goal`**

## 0. Контекст
Откуда фаза взялась и на чём стоит: версия/HEAD проекта, что уже работает, какие решения подписаны, какие внешние источники берутся как есть. Один абзац; чего здесь нет — исполнитель считает неизвестным.

## 1. Технический дизайн высокого уровня (без деталей реализации)
Из каких частей состоит решение и как они связаны: границы, данные между ними, контракт наружу.
**Деталь реализации сюда не пишется** — какими файлами, в каком порядке и каким кодом это сделано, решает `docs/PLAN-<n>.md`.

## 2. Фичи
Фича = вертикальный срез через все слои, демонстрируемый сам по себе, размером в одно свежее окно контекста.
Формат строки: `id · user story · «готово» · команда чека · after: · [P]`
«Готово» — всегда условие, которое доказывает названная команда: нет команды — нет «готово».
`after:` — фичи, без которых эта не стартует (`—`, если первая); `[P]` — можно параллельно с сёстрами, если множества записи не пересекаются.

- **F1 Вход по ссылке из письма** · как пользователь, я захожу в <проект> без пароля · готово, когда ссылка из письма открывает главную, а просроченная — экран «ссылка истекла» · чек: `make test-auth` → `AUTH_OK` · after: — · [P]
- **F<n> <имя>** · как <роль>, я <что получаю> · готово, когда <наблюдаемое состояние> · чек: `<команда>` → `<ожидаемый вывод>` · after: <id или —> · [P]

## 3. Инварианты и границы
Что верно на всём протяжении фазы и проверяемо в любой момент; и чего фаза не делает.
- <инвариант — одна проверяемая строка>
- Каждый чек: команда и её вывод в транскрипте **и** файл `docs/evidence/<fid>-<check>-result.txt`.
- Вне объёма: <что сюда не входит>

## 4. Стоп-точки
Стоп-точка — пауза, не провал: исполнитель пишет `STOP: <id> <что расходится>` в `docs/PROGRESS.md` и останавливается. Это **выполненный goal**. Оператор отвечает одной строкой — и работа идёт с неё.
- **STOP-1 <название>** — срабатывает, только если <точное условие>. Resume-строка оператора: `Продолжай по SPEC-<n> с <фича>; <развилка> решена так: <…>`.
- Остальные неясности решает исполнитель в PLAN и отмечает в `docs/PROGRESS.md` `## Notes`.

## 5. Артефакт закрытия
То, что заказчик ЗАПУСКАЕТ. Гейт на промежуточном артефакте (зелёный чек, сгенерированный файл, отчёт) — веха, не закрытие.
- Запуск: `<команда, которую набирает заказчик>` → <что он видит своими глазами>.
- Плюс к нему: `docs/STATUS.md` с датой гейта, `docs/evidence/*-result.txt` по каждому чеку, один коммит на фичу.
