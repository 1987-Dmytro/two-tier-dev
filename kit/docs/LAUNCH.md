# LAUNCH — строка запуска исполнителя, судьи заявлений и парный контрольный прогон

Кит v3.3 — **судья на заявлении**, а не на действии: «кусок готов» — коммит, его судят git-хуки кита и `abide check`; «фаза готова» — конец хода, его держит `spec-gate` по пунктам спеки; «плечо готово» — отчёт фазы и один круг `/verify-phase`. Между заявлениями модель-судья молчит.

## Запуск исполнителя
Строка запуска фазы — в `docs/PROCESS.md` проекта, раздел «Строка запуска исполнителя»; её пишет тимлид по таблице Environment. Из корня проекта; последний аргумент строки — стартовый запрос `"$(cat docs/PROMPT.txt)"` после `--` (шаблон `docs/PROMPT.template.txt`): фаза стартует без ручного набора — `claude "query"` открывает интерактивную сессию со стартовым запросом (cli-reference).

**Предохранитель окна — `bin/check-window && ` в начале строки** (F5). Один ход `claude -p` на `claude-haiku-5-5` (подписка: `env -u ANTHROPIC_API_KEY`) читает событие `rate_limit_event`: `unifiedWindows.five_hour.utilization` и `unifiedWindows.seven_day.utilization` — доли от 0 до 1, их × 100 сравниваются с порогами `budgets.json` проекта. Поле не документировано — единственное исключение из C2 (журнал intent 10.10); документированный `rate_limits.*.used_percentage` приходит только статус-строке идущей сессии (statusline), его показывает мод `limits` в сессиях оператора.
- окно 5 ч выше `window_five_hour_pct` (40 %) или неделя выше `window_seven_day_pct` (85 %) — отказ до старта сессии: печатаются оба числа и время сброса, `claude` не запускается; ниже — `&&` пускает строку дальше;
- `--repair` — плечо починки: порог окна 5 ч — `window_repair_pct` (70 %); `bin/verify-phase` проверяет окно так же перед клоном — в `claude -p` воркфлоу на лимите не ждёт сброса, а падает (workflows);
- числа не сняты (нет входа в аккаунт, нет события, поле исчезло) — отказ с причиной;
- `--override` — единственный обход любого отказа: флаг пишется в строке (`bin/check-window --override && …`) словом оператора, обход печатается вместе с числами.

Флаги строки:
- `--permission-mode auto` (D2): `defaultMode: "auto"` из `.claude/settings.json` не действует, флаг перекрывает настройки (permission-modes);
- `--model claude-opus-5-5` — полным id: алиас `opus` меняется сам (model-config);
- `--effort ultracode` — `xhigh` и ultracode на сессию: Claude сам планирует воркфлоу на каждую существенную задачу (workflows, model-config). Нужен Claude Code 2.1.203+ и модель с `xhigh`. В `system/init` ultracode не виден — его доказывает флаг в строке;
- `--settings .claude/launch.settings.json` — файл тимлида: `autoMode.environment` (доверенная инфраструктура: из настроек проекта `autoMode` не читается, из `--settings` — читается, auto-mode-config), `enabledPlugins` и `skillOverrides` по таблице Environment;
- `--strict-mcp-config --mcp-config '<json>'` — MCP ровно из строки: срезаются MCP пользователя и плагинов (замер тимлида 07.10);
- `ENABLE_CLAUDEAI_MCP_SERVERS=false` — коннекторы claude.ai не грузятся; кит выключает их и сам (`disableClaudeAiConnectors`), auto memory — тоже (`autoMemoryEnabled: false`);
- `--setting-sources project,local` (v3.2) — настройки, хуки, плагины и скиллы пользователя в сессию исполнителя не входят: его инструменты — из репо, launch settings и таблицы Environment (Agent SDK settingSources, cli-reference);
- `--no-chrome` — встроенный MCP `claude-in-chrome` (настоящий Chrome оператора) в сессии исполнителя выключен (cli-reference);
- `--add-dir /tmp/two-tier-v3/skills` — скиллы пользователя со строкой «да»: из каталога `--add-dir` скиллы грузятся источником `project` (skills, permissions); ещё — если фаза работает вне репо;
- `--` перед стартовым запросом — конец флагов: `--add-dir` и `--mcp-config` берут по нескольку значений, и без `--` запрос уходит к ним лишним каталогом — сессия стартует без запроса (замер 09.10: `claude -p --add-dir <каталог> "<запрос>"` — «Input must be provided», с `--` — ответ).

`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` в строке больше нет (v3.3): Claude Code с 2.1.287 её не читает (mods overview), а Compact Adviser, которому она была нужна, у исполнителя выключен.

Ключ Jev — `TYPESAFE_API_KEY` в окружении терминала, из которого идёт строка (не в репо, не в evidence, не в журналах); строку его длины печатать можно, значение — нельзя. Без ключа молчит только Jev-часть: `abide check` коммита — пропуск (коммит проходит, строка в журнале), Belay пропускает, ячейка Jev отчёта фазы — «молчит», `bin/jev` выходит с кодом 2; правила кода коммита и `spec-gate` решают и без ключа.

## Коммит — судьи кода и `abide check`
`bin/two-tier-init` и `bin/two-tier-upgrade` ставят `git config core.hooksPath .githooks` (githooks): хуки git кита судят и коммит из подпроцесса.
- `.githooks/commit-msg` — сначала код, закрыт на отказ: `no-secret-values` (значение секрета из окружения или литерал вида ключа в добавленной строке любого файла и в сообщении), `evidence-anonymized` (почта, кроме `noreply@` соавтора, или домашний путь в `docs/evidence/` и в сообщении), `team-lead-files` (файл списка `owner` без «Тимлид:»), `no-delete` (удаление — только `git mv` в `docs/archive/`); отказ называет правило и файл, а не найденный текст.
- Затем `abide check --json --phase edit --diff <staged patch>` по рубрике тимлида `.abide/rubric.json`, до 30 с: от 0,8 — отказ один раз, с правилом и файлом; тот же дифф ещё раз проходит как «rejected» — последнее слово за исполнителем, отклонённое читает тимлид; 0,5–0,8 — заметка; ошибка, таймаут, нет ключа — пропуск.
- `.githooks/pre-push` — `no-force-push`: push, который переписывает ветку удалённого репо (не fast-forward), — отказ при любом написании (`--force`, `+ветка`, `git -C`); новая ветка и fast-forward проходят.
- Каждое решение — строка журнала `commit-judge.jsonl` в `docs/evidence/` (решение, судья, правило, файлы, оценка, хеш диффа — без сообщения и содержимого). Хуков Abide на правку и ход у исполнителя нет.

## Конец хода — `spec-gate`
Stop-хук кита `.claude/hooks/spec-gate.mjs` держит конец хода кодом по **пунктам** SPEC фазы — строкам `F<n>.<k>` под строкой фичи: у каждого пункта — строка `F<n>.<k> <сырой вывод пробы>` в `docs/evidence/F<n>-*-result.txt`, у фичи — её маркер отдельной строкой; ветка запушена; голова `docs/PROGRESS.md` (раздел «## Голова») называет сделанное, следующий шаг оператора и срок и переписана в этой сессии (сессия без коммитов кода на уже закрытой фазе — в этой фазе); `VERDICT: PASS` полного круга `/verify-phase` для HEAD и точечный PASS (`FEATURES: F<n>`) по каждой фиче, изменённой после него. Комплект судится по запушенному HEAD: стартовый запрос, SPEC фазы, PROGRESS, evidence фич и файлы вердикта читаются из HEAD, и любой из них, который `git status` называет изменённым, неотслеживаемым или удалённым, держит ход по имени (журналы `spec-gate.jsonl`, `commit-judge.jsonl`, `jev.jsonl` и отчёт фазы — не комплект). Полный комплект — `SPEC_GATE_OK`, ход кончается; новая строка `STOP: <id>` с причиной SPEC §4, вопросом и resume-строкой рядом — тоже, один раз, и только из запушенного HEAD; иначе ход продолжается, блок называет id недостающего пункта. Jev хук не спрашивает.
- Режимы: `SPEC_GATE=off · shadow · active` в окружении, иначе `mode` в `.claude/spec-gate.json` (капы и вопрос ячейки Jev — файл тимлида). `off` — молчит; `shadow` — только строка журнала; `active` — блок. `claude -p` приёмки и пар `check-harness` идут с `SPEC_GATE=off`.
- Предохранители: 12 блоков и 3 ч на сессию, один список три раза подряд — пропуск `no-progress`, фоновые задачи и `AGENT_STOP` — пропуск. Каждое решение — строка журнала `spec-gate.jsonl` в `docs/evidence/` проекта; пропуск с причиной — строка отчёта фазы.

## Плечо — отчёт фазы и один круг приёмки
- `bin/phase-report` собирает кодом `phase-report.md` в `docs/evidence/`: матрица «пункт × коммиты, проба, наблюдение», списки «пункты без коммитов», «коммиты без пункта», «пункты без пробы», счёт судей коммита, пропуски хука и статус ячейки Jev — «подтверждает / противоречит / молчит», в тени: ответ, ошибка и таймаут Jev ход не меняют.
- Приёмка — один круг: `bin/verify-phase` из свежего клона запушенного HEAD проверяет все фичи; после починки — `bin/verify-phase F2 …` только по затронутым фичам (вердикт с строкой `FEATURES: F2`), второго полного круга нет. Выжившая мутация и пункт, не подтверждённый собственной командой проверяющего и её сырым выводом, — блокирующие.

## Слой Jev в харнесе кита
У исполнителя фаза — один ход, его заявления — коммит и конец хода. Toolgate, хуки Abide на правку и ход, Compact Adviser и Steer-or-Queue у исполнителя выключены — их события (каждое действие, сообщение человека посреди хода, совет человеку у терминала) есть только в сессиях оператора; их прежние файлы — в `docs/archive/` two-tier-dev (`kit-v3.2/claude-config/`). Хук на действие (PreToolUse, PostToolUse, UserPromptSubmit), который ходит в сеть или зовёт модель, — красный в `bin/check-harness`. Остаются: Jev Belay — тень (только журнал); мод `handoff` — хендофф и свежий контекст на 70 % окна; `bin/jev` — типизированные вопросы Jev; плагины слоя — `enabledPlugins` и `pluginConfigs` launch settings по таблице Environment, пины моделей — `env` launch settings.

Харнес кита — `.claude/settings.json`: `worktree.baseRef: "head"` (worktree агента воркфлоу ветвится от HEAD, а не от ветки по умолчанию), `workflowSizeGuideline: "medium"` (<10 агентов — совет модели, не потолок), узкие `permissions.allow` на `bin/check-*`, `bin/gate-*`, `make ci`.

## Контрольный прогон — парный
`bin/check-harness` берёт строку из `docs/PROCESS.md` (нет его — из шаблона кита) и гоняет её часть после `bin/check-window && ` как есть с `-p` на копии харнеса — свой каталог на запуск во `/tmp/two-tier-v3`:
`env -u ANTHROPIC_API_KEY` (только подписка), `--max-turns 3`, `--output-format stream-json --verbose`, без `--bare` (он пропускает хуки).
- run1 — заметка в `STEER.md` с маркером: маркер оказывается в файле-пробе;
- run2 — с `AGENT_STOP`: пробы нет, прогон остановлен на первом вызове, в выводе причина kill-switch;
- allow — под `dontAsk`, правила `permissions.allow` кита — через `--allowedTools`: в `-p` папка не доверена, и правила из `.claude/settings.json` не действуют (permissions, «What runs before you trust a folder»), в интерактивной сессии — после диалога доверия. `bin/check-*` идёт, команда вне правил — отказ;
- плюс: в `system/init` режим `auto` и `apiKeySource none`; поля settings по SPEC; `claude doctor` без ошибок настроек.
- копия харнеса несёт свой CLAUDE.md, где оператор авторизует пробы. Правила кита («`git add` по точным путям») агент воркфлоу ставит выше промпта скрипта и иначе сам не пробует то, что должен отказать хук.

Гонять при смене модели, релизе Claude Code и правке харнеса или таблицы; итог «до и после» — строкой в CHANGELOG кита.
