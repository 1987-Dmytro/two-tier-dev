## 1. Дизайн высокого уровня
- **Запуск без `/goal`.**
  - Файл стартового запроса — `docs/PROMPT.txt`: `Read first:` (до 3 файлов), фаза и её SPEC, «сделано = гейт фазы и PASS `/verify-phase`», стоп — только по SPEC §4. Строка запуска PROCESS кончается этим запросом аргументом.
  - `check-budget` находит SPEC фазы по `Read first:` этого файла. Шаблон GOAL, бюджет `goal_chars` и проверка END STATE уходят в `docs/archive/` (`git mv`); упоминаний `/goal` в ките не остаётся.
  - Проект с `docs/GOAL.txt` переводит `two-tier-upgrade`. В этом репо файл тимлида переносит тимлид на приёмке; до того `check-budget` читает прежнее имя.
- **`bin/jev`** — один скрипт для обоих ярусов, Node без зависимостей: файл вопросов и state со stdin → JSON ответов. Ключ — из окружения, модель — пином, таймаут, код выхода ≠ 0 на ошибке. Каждый вызов — строкой в журнале расхода.
- **`spec-gate`** — Stop-хук кита (эскиз — research §5.1, предохранители — §10.2).
  - Код, $0. По строкам фич SPEC фазы: evidence с маркером у каждой; ветка запушена; голова PROGRESS обновлена в этой сессии; вердикт `/verify-phase` — PASS для HEAD. Полный комплект → `SPEC_GATE_OK`, ход кончается. Неполный → конец хода блокируется, причина — список недостающего, составленный кодом.
  - Jev — только на нечётком, одним вызовом `bin/jev`: новая строка `STOP: <id>` называет одну из причин §4 и несёт вопрос и resume-строку; голова PROGRESS говорит, что сделано, следующий шаг оператора и когда; текст evidence не противоречит «готово» фичи. Ошибка или таймаут Jev → решает код один.
  - Предохранители: кап блоков и времени на сессию; три блока подряд с одним списком → пропуск с причиной `no-progress`; `AGENT_STOP` сильнее хука. Режимы `off · shadow · active`; в `claude -p` приёмки и парных прогонов — `off`. Каждое решение — строкой в `docs/evidence/spec-gate.jsonl`.
  - Вопросы и пороги — один файл кита, владелец — тимлид.
- **Abide в ките.** Хуки Abide — в настройках проекта, а не пользователя. Правила пишет тимлид по SPEC §3 в файле инструкций проекта (`CLAUDE.md`); рубрику из них он компилирует и калибрует на истории репо до запуска фазы, и она — файл тимлида. Исполнитель рубрику не компилирует и не правит. Режим — заметка: Abide требует починки в том же ходе и конец хода не блокирует. В этом репо: `CLAUDE.md` и `.abide/rubric.json` — 13 правил, калибровка 09.10 на 20 фрагментах и 8 коммитах — ложных срабатываний 0.
- **Toolgate «только отказ».** PreToolUse-хук кита поверх `toolgate decide` печатает только `deny`; на `allow` и `ask` молчит — действует штатный поток прав. Политика исполнителя — файл тимлида.
- **Плагины слоя.** Jev Belay и Steer-or-Queue — тень (только журнал), Compact Adviser — `hint`, `handoff` — 70 % и `/clear`. Включение и режимы — `enabledPlugins` и `pluginConfigs` шаблона launch settings; источник — таблица Environment.
- **Скиллы и пробы «по задаче».** Скилл со строкой «да» доходит до сессии документированным способом при `--setting-sources project,local`. Quicksilver, Jev SEO и Jev Browser в сессию по умолчанию не входят: их наличие на машине доказывает проба. Чек UI — шаблон `bin/check-ui`: сценарий Jev Browser → маркер.
- **`check-harness`** сверяет всё это с таблицей Environment по `system/init` и файлу launch settings и несёт пробы хуков слоя — на главной сессии и на агенте воркфлоу.
- **Расход.** Одна команда складывает журналы инструментов слоя в вызовы, токены и евро — отчётом, без планки.

## 3. Инварианты и границы

- C4: живые проекты не трогаются. Работа — только в репо и во `/tmp/two-tier-v3`. Настройки и установки пользователя (`~/.claude`, политика и журналы Toolgate, конфиг Abide, скиллы пользователя) исполнитель читает, но не правит; новая установка уровня пользователя — STOP-INPUT с точной командой.

- C3: платное — только Jev; потолка на плечо нет (PROCESS §Деньги). Контрольные `claude -p` — на подписке (`env -u ANTHROPIC_API_KEY`), не больше 3 ходов, с `--setting-sources project,local`. Модели — полными id.
- C6: ключ TypeSafe — только из окружения: не печатается, не пишется в репо, в evidence и в журналы внутри репо. В Jev уходят финальное сообщение, голова PROGRESS, имена файлов, маркеры и строки диффа этого репо; содержимое вне репо и секреты — нет.

- Хук слоя не меняет поток прав: не печатает `allow`, не задаёт вопрос, на который в сессии некому ответить, и при ошибке пропускает.
- Агенты воркфлоу правят только в своих worktree или только читают; коммит делает главная сессия, `git add` точными путями.
- Репо публичный: evidence и сообщения коммитов — счётчики, коды выхода, маркеры и пути от корня репо или от `/tmp/two-tier-v3`. Без почты, id аккаунтов и организаций, имён клиентов и путей домашнего каталога.

- Вне объёма: перевод projekt_1_telefon, правка скилла `team-lead`, jev-mcp, Toolgate с `ask`, agent teams.
