## 1. Дизайн высокого уровня
Условий «готово» здесь нет — все они пункты §2.
- **Контекст (F1).** Мод `handoff` работает в сессии человека во вкладке Code: команда `/handoff` есть везде, где мод загружен, сам он срабатывает только в главной нити сессии, к которой подключена поверхность (вкладка подключается как `desktop`; в `-p` поверхностей нет); опции (порог, каталог, режим Jev) берёт из профиля проекта `.claude/settings.local.json`, настройки пользователя — запасной источник: проба читает их как есть и не правит. Поле `autoCompactWindow` в шаблоне профиля — страховка: пока мод работает, сжатие не срабатывает. Признак работы — строка движка и `/handoff status`, а не сверка файлов; строку Environment шаблона PROCESS (40 %, поле сжатия) сверяет тот же чек.
- **Сессия фазы (F2).** Метка `.claude/phase-session.json` (вне git) называет сессии фазы; ведёт её мод `phase-start` (команда, отправленный запрос, `classic.SessionStart` с `source`), читают `spec-gate` и `steer.sh`. Хук закрыт на отказ для сессии фазы: сессия вне метки со своим транскриптом, где до первого ответа модели стоит текст запроса, судится; без файла метки хук судит как v3.4. Для остальных открыт: ответвление Stop-хук узнаёт по транскрипту — первые записи несут `sessionId` родителя, — служебную сессию — по отсутствию текста запроса. Профиль корня кита (файл тимлида) правки не требует.
- **Открытый стоп (F3).** Один и тот же стоп — тот, чью строку Resume шлёт `/phase resume`, — отпускает ход столько раз, сколько ход кончается, пока после него нет коммита вне отчётных файлов (`docs/evidence/`, `docs/PROGRESS.md`, `docs/PLAN-*.md`).
- **Линты выдачи (F4, F5, F7).** Планка связана с пунктом, когда id пункта или его ключ `planken:<ключ>` стоит в заголовке или строке её таблицы посадки; пункт ранней планки — отчёт: начинается словом «отчёт:», печатает число, маркер фичи от него не зависит. Путь или команда спеки и запроса существуют в HEAD или названы в строке «Новые пути:» §1; путь для линта — токен в обратных кавычках, который начинается с каталога верхнего уровня из HEAD, или `make <цель>`; слэш-команды, голые имена файлов, пути вне репо, шаблоны с `<…>` и `*` и то, что git игнорирует, не судятся. Вердикт свежего проверяющего несёт пин спеки — 12 знаков `git hash-object` её файла. Все три после выдачи спеки — WARN: выданную спеку правит тимлид.
- **Слово оператора (F6).** Окно доводки — строка §3 спеки: какие файлы тимлида открыты и запас диффа. В окне исполнитель меняет такой файл только командой `bin/operator-word`, коммит — «Оператор: <слово>»; «Тимлид:» из сессии Claude Code (`CLAUDECODE=1`) хук не принимает; фикстуры кита, играющие тимлида, зовут git в окружении своей роли — без этой переменной. Это защита от честной ошибки и след для приёмки, не граница доверия: судья — список таких коммитов в отчёте фазы.
- **Приёмка на Opus (F8).** Каждая стадия `/verify-phase` и всё, что судит по `REVIEW.md`, — `claude-opus-5-5`; ярусы 164 (перечисление — Haiku, чтение и правка — Sonnet) остаются подагентам стройки.
