# Наша система разработки с ИИ-агентами — «оператор · тимлид · исполнитель», кит v3.2

**v3.2 · 09.10.2026 — Jev-слой, без `/goal`: фазу ведёт спека, конец хода держит `spec-gate`.** Как собран v3.2 — `docs/SPEC-v3.2.md` и `docs/PLAN-v3.2.md`. v3.1 (07.10, ultracode по полной) — `docs/SPEC-v3.1.md`; v3.0 (06.10) — `docs/SPEC-v3.md` и `docs/PLAN-v3.md`; v2 (18.09) — в истории git этого файла, кит v2 — в `docs/archive/kit-v2/`. Зачем — `intent/INTENT.md` (N2, D4), как собран v3.1 — `docs/SPEC-v3.1.md` и `docs/PLAN-v3.1.md`.

## 0. Одним абзацем
Оператор ведёт любой проект циклом **intent → прожарка → SPEC → запуск фазы → приёмка → гейт** — без `/goal`: фазу запускает стартовый запрос в строке запуска, конец хода держит Stop-хук `spec-gate` по файлам evidence, а не по словам. Тимлид (Cowork) задаёт результат, проверку, границы и стопы; исполнитель (Claude Code, `claude-opus-5-5`, auto mode, **ultracode** — штатный режим: сам планирует воркфлоу из агентов на каждую существенную задачу) строит путь сам. Объём инструкций держит механика (`bin/check-budget` в CI), а не память; intent живой и закреплён в SPEC пином; харнес — только по официальной документации, каждое поле проверено контрольным прогоном. Повторяемые нечёткие вопросы по документу (заявлено «готово»? правка ломает правило? действие опасно?) судит Jev за центы — хуками и `bin/jev`.

## 1. Роли
| роль | владеет | не делает |
|---|---|---|
| **Оператор** | цель, деньги, три решения: спека да/нет · буква на стопе · гейт (сам запускает продукт) | не шина между ярусами: задача уходит файлами в репо — SPEC и стартовый запрос |
| **Тимлид** | `intent/INTENT.md`, `docs/SPEC-<n>.md`, стартовый запрос `docs/PROMPT.txt`, `docs/PROCESS.md`, `docs/STATUS.md`, ревью, `.claude/launch.settings.json`, правила `CLAUDE.md` и рубрика Abide, вопросы `spec-gate`, политика Toolgate | не пишет шаги реализации |
| **Исполнитель** | `docs/PLAN-<n>.md`, код, коммиты по путям, evidence, `docs/PROGRESS.md` (голова — отчёт фазы) | не правит файлы тимлида (deny `Edit` + lint владения), не проверяет себя сам |
| **`/verify-phase`** | вердикт `VERDICT: PASS` / `NEEDS_WORK` по `REVIEW.md` — сохранённый воркфлоу: проверяющие `claude-sonnet-5-5` по фичам, судья `claude-opus-5-5` | свежий клон и свежий `claude -p` на каждой приёмке, 30 мин; evaluator-субагент — запасной путь |

## 2. Цикл v3.2 — без `/goal`
1. **Intent.** Один живой `intent/INTENT.md` (шаблон `docs/INTENT.template.md`): проблема · результат · сигналы успеха `S1…` · жёсткие ограничения · не-цели · решено и `[NEEDS CLARIFICATION: …]` · эталонные входы · журнал разворотов. Разворот — строка журнала и новый пин, а не поправка поверх SPEC.
2. **Прожарка** по `grilling` — полная на kickoff, дальше только фронтир новой фазы.
3. **SPEC** (шаблон `docs/SPEC.template.md`): шапка `intent/INTENT.md @ <12 знаков hash-object>`; фича — до 600 знаков, `служит: S…`, чек → маркер; стопов четыре.
4. **Запуск фазы** — строка из `docs/PROCESS.md` (`--effort ultracode`, `--setting-sources project,local`), последний аргумент — стартовый запрос `"$(cat docs/PROMPT.txt)"` (шаблон `docs/PROMPT.template.txt`): до 4000 знаков, `Read first:` — до трёх файлов, «сделано» — гейт фазы и PASS `/verify-phase`, стоп — только по SPEC §4, разрешённые действия строкой `Authorized in this phase:`. Ручного набора нет.
5. **PLAN** — шаг 0 внутри запуска: файлы · порядок · риски · доказательство · отклонения от SPEC по докам. Фаза с платными или необратимыми шагами — сначала `/plan-phase` и приёмка плана.
6. **Работа**: коммит на фичу, `git add` по путям, вывод каждого чека — в транскрипте и в `docs/evidence/<F>-<check>-result.txt`.
7. **Конец хода и стоп.** Ход кончается, только когда `spec-gate` видит полный комплект (evidence с маркером у каждой фичи, ветка запушена, голова PROGRESS обновлена, PASS для HEAD) или новую строку `STOP: <id>` — вопрос и resume-строка. Причины: платное или необратимое выше порога · смена объёма · вход оператора · нет прогресса. Развилка, которую SPEC не закрыл, — простейшее прочтение и строка в `## Notes`.
8. **Приёмка** — три слоя: CI на push · `/verify-phase` (`bin/verify-phase` из `/accept` и из «сделано» стартового запроса: свежий клон, гейт, по фиче — свежий чек, пограничные случаи против «готово», мутация; опровергатели; судья; вердикт в `docs/evidence/verify-<sha>.txt`, лимит 30 мин — иначе `VERIFY_TIMEOUT`) · ревью тимлида, до пяти блокирующих находок. Исполнитель гоняет `/verify-phase` до конца фазы и чинит его блокирующие в той же сессии. STATUS пишет тимлид.
9. **Гейт** — оператор запускает продукт и судит по сигналам intent.

## 3. Бюджеты — механикой
`bin/check-budget` читает `budgets.json` (defaults кита; `project` только ужесточает) и печатает OK/WARN/FAIL на правило и `BUDGET_OK`. Знаки — символы Unicode.

| что | предел |
|---|---|
| копия `team-lead` (`docs/drafts/team-lead-v6.md`) · `team-lead-brief` | 80 строк и 12 000 знаков · 150 строк и 15 000 знаков |
| скилл кита · `CLAUDE.md` кита | 4 000 знаков, без `$` с цифрой · 40 строк |
| `intent/INTENT.md` | 6 000 знаков (WARN); маркер неясности — WARN |
| строка фичи SPEC | 600 знаков, `служит:` ссылается на существующий S; маркер неясности в SPEC — FAIL; пин = hash-object INTENT |
| `docs/PROGRESS.md` · PLAN фазы | 60 · 150 строк |
| стартовый запрос `docs/PROMPT.txt` | 4 000 знаков (`prompt_chars`); `Read first:` — до 3 файлов и 50 000 знаков вместе с CLAUDE.md |
| рубрика Abide `.abide/rubric.json` | до 15 правил (`abide_rules`) |
| ревью `docs/reviews/*` | блокирующих — до 5 |
| владение | коммит после merge-base с `main`, меняющий файл тимлида, — только «Тимлид:»; список — на родителе коммита, `budgets.json` в нём; стартовый запрос наследует владение прежнего `docs/GOAL.txt` |

CI (`.github/workflows/two-tier.yml`) гоняет `bin/check-budget` и `make ci` на каждый push и PR; `bin/check-ci <ветка>` засчитывает только прогон текущего HEAD.

## 4. Харнес
- `.claude/settings.json`: модель полным id; effort не задан — ultracode и effort фазы в строке запуска; `worktree.baseRef: "head"` (агент в worktree видит HEAD ветки, а не `main`); `workflowSizeGuideline: "medium"`; узкие allow на `bin/check-*`, `bin/gate-*`, `make ci`; `autoMemoryEnabled: false`; `disableClaudeAiConnectors: true`; deny `Edit` на файлы тимлида (Edit покрывает и Write); хуки exec form с `${CLAUDE_PROJECT_DIR}`.
- `AGENT_STOP` в корне — kill-switch: `continue: false` со `stopReason`, вызов не выполняется, прогон останавливается — и у главной сессии, и у агента воркфлоу. Строка в `STEER.md` — заметка фактом в `additionalContext`, только главной сессии (у агента во входе хука `agent_id`).
- Агенты воркфлоу правят только в своих worktree или только читают; коммит — главная сессия; push в `main` запрещён (`kit/CLAUDE.md`, его читает и классификатор auto mode).
- **Окружение = таблица.** Таблица Environment в `docs/PROCESS.md` (инструмент · форма · id · вкл · фича · установка · удаление) → `enabledPlugins` и `skillOverrides` в `.claude/launch.settings.json` и строка запуска: `--permission-mode auto --model claude-opus-5-5 --effort ultracode --settings .claude/launch.settings.json --strict-mcp-config --mcp-config …`. Флаги — `docs/LAUNCH.md`.
- **Слой Jev** (D6) — проводкой кита, строками таблицы: Stop-хук `spec-gate` (код по файлам, Jev — на нечётком, капы, при ошибке пропускает); Abide на каждой правке (правила тимлида в `CLAUDE.md`, рубрика — его файл; требование починки, конец хода не держит); Toolgate «только отказ» (`toolgate decide`, печатает только `deny`); Belay и Steer-or-Queue — тень, Compact Adviser — `hint`, мод `handoff` — хендофф на 70 % окна; Quicksilver, Jev SEO, Jev Browser — по задаче, с пробами. `bin/jev` — типизированные вопросы Jev обоим ярусам; `bin/check-spend` — расход за плечо.
- `bin/check-harness` — пара этой строкой: `system/init` = таблица (плагины, MCP `connected`, скиллы, CLI, флаги) — `ENV_OK`; заметка доходит, стоп-кран останавливает, allow-правила работают, `claude doctor` чист — `HARNESS_OK`; deny, отказ широких команд, стоп-кран и заметка — на главной сессии и на агенте воркфлоу — `HOOKS_OK`; конец хода по файлам — `GATE_HOOK_OK`; правила правок — `ABIDE_OK`; Toolgate «только отказ» — `TOOLGATE_OK`. Итог «до и после» — в CHANGELOG.

## 4а. Три судьи по цене вопроса
- **Код** — где ответ даёт grep или файл: маркер в evidence, ветка запушена, PASS для HEAD. Бесплатно и без ложных срабатываний.
- **Jev** — где вопрос ограничен документом и повторяется на каждом ходе или правке: STOP с вопросом и resume-строкой? голова PROGRESS полна? правка ломает правило `CLAUDE.md`? действие опасно? Доли цента и доли секунды; порог — по своим меткам, ошибка или таймаут — решает код.
- **Свежий агент** — где нужно воспроизвести или синтезировать: `/verify-phase` (свежий клон, мутации, опровергатели, судья). Дорого — только на приёмке.

## 5. Самоулучшение
- Правило харнеса, кита или скилла меняется только по `docs/OFFICIAL-SOURCES.md` (цитата, URL, дата) или по повтору одной ошибки не меньше двух раз — и без спора с официальным.
- Сначала механизм (хук, чек, скрипт, поле), проза — лишь когда механизма нет; правка проходит абляцию (тот же сценарий свежими субагентами со строкой и без, `claude/evals-2026-10-06/`); «одно вошло — одно вышло» внутри бюджета.
- На стопе урок — строкой в каталог развилок проекта (`docs/PROCESS.md`), скилл на стопе не правится. Ретро фазы и новая модель — свип источников; найденное и удалённое — строкой в CHANGELOG.

## 6. Где что живёт
Кит — `kit/` (`bin/two-tier-init` кладёт его в корень проекта). Инструменты проекта — `kit/bin/`. Шаблоны — `kit/docs/`. Копии скиллов Cowork — `docs/drafts/`. История — `docs/archive/`: ничего не удаляется, выводимое уходит туда `git mv`.

## 7. Как начать и как перевести
- **Новый проект:** `git init` → `<two-tier-dev>/bin/two-tier-init .` → `bin/check-budget` → `BUDGET_OK`. Тимлид пишет intent, SPEC, стартовый запрос `docs/PROMPT.txt` и `launch.settings.json` коммитами «Тимлид:», оператор запускает исполнителя строкой из `docs/PROCESS.md` (флаги — `docs/LAUNCH.md`).
- **Живой проект v2:** `<two-tier-dev>/bin/two-tier-upgrade <путь>` → ветка `kit-v3`: механика v3, прежние файлы — в `docs/archive/kit-v2/`, раздутые PROGRESS и PLAN — в архив с датой, отчёт `docs/upgrade-v3.md` (что осталось тимлиду, исполнителю и оператору). Проект кита v3.1 переходит тем же скриптом: `docs/GOAL.txt` → `docs/PROMPT.txt` отдельным коммитом «Тимлид: …». Push делает исполнитель проекта по своему стартовому запросу; merge — после приёмки.
