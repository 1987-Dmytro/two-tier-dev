# Наша система разработки с ИИ-агентами — двухуровневый цикл «оператор · тимлид · исполнитель»

**v1.1 · 06.09.2026** (v1.0 — утро 06.09). Выведена из практики, а не придумана: одна фаза проекта-источника (маркетинговый LLM-инструмент, сентябрь 2026) — 29 сессий исполнителя, 25 рулингов (а)…(y), ретро процесса 03.09, девять разборов остановок 04–06.09. Живёт в двух скиллах (`team-lead` для Cowork, `brain-init` для Claude Code) и в документах каждого проекта. Этот файл — описание системы целиком, чтобы её можно было применить к следующему проекту и передать стороннему человеку.

## 0. Одним абзацем

Один человек — **оператор** — ведёт разработку через два уровня ИИ: **тимлида** в Cowork (скилл `team-lead`) и **исполнителя** в Claude Code (репозиторий, оснащённый `brain-init`). Оператор владеет целью, деньгами и пониманием того, что делает система; тимлид — файлом фазы, приёмкой и журналом решений; исполнитель — кодом, тестами, коммитами и файлом прогресса. Прямого канала между уровнями нет: оператор переносит **стандартный промт** вниз и отчёт **«Выполнено, проверь»** вверх, а сам принимает только решения — по таблицам, в один визит. Система оптимизирует не скорость написания кода, а **стоимость проверки**: верификация обязана оставаться дешевле сборки, а истина считается **продуктовой** (оператор видит вывод рядом с эталоном), не процессной (зелёные тесты ничего не закрывают).

## 1. Три роли — и что никогда не делегируется

| роль | где | владеет | никогда не делает |
|---|---|---|---|
| **Оператор** | Claude Desktop / Cowork + Claude Code | цель, метрика, каждое бизнес- и денежное решение, понимание системы; переносит промт и отчёт | не отвечает на вопросы, которые файл фазы мог ответить заранее (это дефект файла фазы, а не оператора) |
| **Тимлид** | Cowork-сессия со скиллом `team-lead`, репо смонтировано | файл фазы, приёмка (дифф · артефакт · собственный прогон проверки), журнал решений, STATUS, эталоны (разметка вслепую), кодбук | не пишет продуктовый код, не правит файлы исполнителя, не принимает работу по прозе — только по result-файлам |
| **Исполнитель** | Claude Code в репо (свежая сессия каждый раз; усилие, оркестрация и строка запуска — поля харнеса, PROCESS «Harness fields») | реализация, тесты, коммиты по пути, файл прогресса, ранбуки, платные раны | не правит файлы тимлида (`permissions.deny`), не принимает свою работу, не добавляет тест/пин/гард/леджер, которого файл фазы не просил |

Язык: разговор и карта — на языке оператора; код, промты, артефакты, коммиты — на английском.

## 2. Два скилла и граница между ними

**`team-lead` (сторона Cowork).** Универсальная карточка скилла в аккаунте Claude: принципы и минимальная процедура — роли, продуктовая истина, файл фазы с каталогом развилок, файл прогресса, стандартный промт, приёмка, диета закона, видимость для оператора, честность, самоулучшение. Её версия — это **changelog того, чему система научилась**: v2.1 (двухуровневая схема) → v3 (03.09: один файл фазы, один файл прогресса, без `/goal`, рулинг ≤12 строк) → v3.1–3.4 (04–05.09: каталог развилок, триаж красного бара, поля записи по ноге) → v3.5–3.9 (05.09: деньги — линия на ран, ставка целого рана, кап из пробного расчёта, закрытие по пост-рановому чтению, верификатор до покупки) → v3.10 (06.09: диета — только паттерны) → v3.11 (06.09: регистрация ≠ открытие линии — якорь берётся в платной сессии; стоящий закон проекта бьёт рулинг по механике, без остановки). Каждую новую карточку предлагает тимлид, сохраняет оператор.

**`brain-init` (сторона Claude Code).** Набор, который делает репозиторий пригодным для работы исполнителя без памяти между сессиями: `CLAUDE.md` (≤80 строк: где живёт истина, владение файлами, рабочий цикл, правила, стек); `.claude/settings.json` — `permissions.deny` на файлы тимлида, хуки `SessionStart` (инъекция кэша), `Stop` (штампы сессии в `knowledge/`), `PreToolUse` (отказ sweeping-командам `git add -A`, `make fmt .`); `.claude/commands` (`/plan-phase`, `/report`, `/save`, `/close`); `.claude/rules/*.md` — инварианты по путям; `knowledge/` — Obsidian-vault (`hot.md` ≤40, `daily_logs`, `decisions`, `runbooks`, `templates`, `index`); граф кода (`graphify`). Модуль **M6 «two-tier»** добавляет шаблоны файла фазы и файла прогресса, стандартный промт, deny-правила. Дельты **M6 v2** (03–04.09: инъекция только PROGRESS + `git log`, один `/checkpoint` вместо `/save`+`/close`, отчёт как запись в PROGRESS, без stop-хука для `/goal`, каталог развилок и `class:` открытого стопа в шаблонах) — предложены и записаны (`claude/brain-init-m6-v2-deltas.md`), в проекте-источнике ещё **не применены**: хуки бюджета `hot.md`/daily-log по-прежнему штампуют каждую сессию.

**Граница — главное правило системы.** Паттерн → скилл. Механика проекта (команды, флаги, цены, пути, платформа) → `docs/PROCESS.md` проекта. Правила фазы → `docs/PHASE-<фаза>.md`. Решения по ходу → рулинги в `docs/reviews/`. Дефолты шаблонов → `brain-init`. Тест для строки скилла: **прочитается ли она так же в проекте на другой платформе, в другой валюте, с другим исполнителем?** Если нет — она принадлежит проекту, а в скилл идёт только её паттерн.

## 3. Артефакты и потолки

| файл | пишет | потолок | что это |
|---|---|---|---|

## 4. Цикл

```
СТАРТ ФАЗЫ   интервью (вопрос · метрика · данные · запреты) → PHASE v1 (с каталогом развилок и дефолтами денег) → стандартный промт
                │
СЕССИЯ       брифинг ≤5 строк → оператор: промт (усилие — поле харнеса) → исполнитель: ритуал старта → ОДИН пункт → проверка показана
ИСПОЛНИТЕЛЯ  → коммит по пути → PROGRESS → «done» или стоп (запись, конец хода) → оператор: «Выполнено, проверь»
                │
ПРИЁМКА      дифф · артефакт · собственный прогон проверки · числа только из result-файлов · свежий верификатор (деньги, секреты, ввод)
ТИМЛИДА      красное → триаж: (1) полнота рана (2) эталон и грейдер (3) закон;  зелёное → галочка · строка решения · STATUS с датой
                │
СТОП         рулинг ≤12 строк → разбор паттерна (класс · корень · предвидимо?) → тот же день: PHASE по ревизии / PROCESS (механика) /
             карточка скилла (паттерн) / харнес исполнителя → оператору три строки: паттерн · что изменилось · что предотвращает
                │
ПЛАТНЫЙ РАН  $0-подготовка (пробный расчёт: пины · популяция · таблица решений · цена с платформы · кап из него · жёсткий стоп · ранбук)
             → свежий верификатор по денежным путям → тимлид читает пробный расчёт и HEAD → платная сессия: регистрация ОТКРЫВАЕТ линию
             за минуты до создания (никогда сессией раньше) → создание → смок (короткий ·
             средний · САМЫЙ ДЛИННЫЙ) → GO → ран → удаление → запись рана → пост-рановое чтение → закрытие линии → чтение принято триажем
                │
ЗАКРЫТИЕ     гейт продуктовой истины (оператор видит N строк под сидом рядом с эталоном и говорит, что верно) → отчёт этапа →
ФАЗЫ         метрики ретро с порогами диеты → одна строка ретро → дефолты файла фазы выросли, закон исполнителя — нет
```

**Единица работы** — один пункт за сессию исполнителя; пункт — единица *проверки*, не размера: несколько $0-правок под одной проверкой — один пункт; платный ран — своя сессия, его ранбук пишется и перенацеливается сессией раньше. **Каденция:** ≥2 сессии исполнителя в день, ≤1 остановка в день, приёмка в тот же день. Две неудачные поправки в одной сессии — не кормить дальше: одна строка решения, свежая сессия. Никогда не считать, что сессия исполнителя жива: каждая передача пишется для свежей.

## 5. Деньги — паттерны (механика с командами — в `PROCESS.md` проекта, раздел «Деньги»)

- **Один платный ран = одна денежная линия**: своё имя, свой якорь — чтение ВНУТРИ платной сессии, за минуты до создания ресурса, никогда сессией раньше (старый якорь пьёт каплю всегда-включённых ресурсов в ссылку закрытия, и полоса допуска закрывается за часы), кап рана как её кап, закрытие по записи рана в той же сессии. Открытая многорановая линия нового рана не несёт. Регистрация читает гард **своей** линии; дефолтное имя линии в эмиттере — следующий отказ. **Регистрация ≠ открытие линии:** запись (пины, граница, FITS, железо, цена, бэкстоп) пишется и читается за $0 — тимлид до покупки читает пробный расчёт и код на HEAD; если эмиттер регистрирует и открывает одной командой, она выполняется в платной сессии, а регистрация читается на приёмке против пробного расчёта. Рулинг и PROCESS.md разошлись по механике — прав PROCESS.md: исполнитель идёт по нему, называет противоречие в PROGRESS, не останавливается.
- **Ставка — среднее ЦЕЛОГО рана самого медленного хоста** (n = единицы рана), никогда смок из трёх и никогда заимствованная у сиблинга. Дорогой угол (максимум на каждой единице) считается и показывается; когда он не влезает — нога выпускается FITS на среднем угле с капом как жёстким стопом и без полосного гейта.
- **Кап цитируется из пробного расчёта**, который его назвал, — не печатается из текста опции или старой оценки. Ограда для более позднего шага — оценка, не кап: перерасчёт на регистрации этого шага.
- **Железо и цена — поля записи**, прочитанные с платформы за $0 (оба имени: для создания и для прайса), не константы эмиттера. Бэкстоп платформы выводится из капа по зарегистрированной цене; заимствованная константа минут, кусающая первой, ограничивает чтение, а не деньги.
- **Смок — самый длинный рендер первым**: железо, которому не хватает, падает на трёх единицах, не на восьмидесяти. Раннер пишет ответ-ошибку упавшей единицы и выходит ненулевым; клиент читает её и удаляет ресурс сразу, а не ждёт дедлайн. Новая форма строки ответа читается **всеми** читателями файла в той же починке.
- **Закрытие линии — по её пост-рановому чтению**, снятому после освобождения ресурса и до любого следующего рана (ссылка гейта — последнее открытое чтение; дорановое отказывает навсегда). Линия без такого чтения закрывается по одному биллинговому walk'у в своём окне и позднего чтения не берёт. Биллинг запаздывает — частичный walk отказывается и повторяется в ритуале старта следующей сессии.
- **Валидность платного чтения**: ран считается, только когда каждая единица отвечена и распарсена; сервинг-отказ (нехватка памяти, крах) двигает сервинг, не инструмент; перекупка — следующий номер на своей линии.
- **Потолок цикла — слово оператора** по таблице (варианты · что влезает · когда спросят снова); якорь никогда не перегенерируется; всегда включённые ресурсы капают в каждое открытое окно; teardown доказывается листингом.

## 6. Честность и научная дисциплина

Ни одного числа без сида, конфига, происхождения и файла. Претензии **предрегистрируются**: чтения-не-бары там, где оператор решает по таблице; бары с критериями там, где делается заявление; **одна попытка на замороженном наборе**; красный бар закрывает вопрос, под который был зарегистрирован, — и принимается так же спокойно, как зелёный; неполный ран не закрывает ничего и называется неполным. **Инструмент на замороженном наборе — байт-в-байт тот, что взял dev-бар**; косметика закона встаёт в очередь за попыткой. **Сожжённый набор понижается до чтения**, следующий бар нуждается в НОВОМ наборе из **популяции продукта** (источники, которые продукт реально читает), никогда из надмножества. Решение называет **команду**, чей вывод — число, а не число; правило без команды никто не проверяет. Синтетика помечается и никогда не попадает в замороженные наборы; витрины читают result-файлы и громко падают.

## 7. Как система учится

Каждая остановка — урок, без исключений: класс (плановое чтение · развилка · дефект · деньги · процесс) → могла ли ответить файл фазы? → какое правило входит и **куда** (файл фазы тем же днём; PROCESS.md — если это механика; карточка скилла — если паттерн; харнес исполнителя). Класс, встреченный дважды, становится дефолтом каталога развилок; дефолт, не выстреливший за фазу, удаляется на ретро. Находка верификатора **до** покупки — остановка, которой не случилось: проходит тот же разбор. **Метрики ретро с порогами диеты:** строки верификации ÷ строки продукта > 3 · процессные коммиты > 25 % · остановок > 1 в день · сессий исполнителя < 2 в день · артефакт над потолком · предвидимых остановок > 0 — пересечение любого = следующая сессия не фича, а диета, и диета может означать, что растут дефолты файла фазы, а не закон исполнителя. Три денежных остановки за день = у шаблона файла фазы нет раздела «Деньги» — пишутся его дефолты разом, не по правилу на остановку.

Честный счёт трёх дней: 04.09 — 8 сессий, 4 остановки; 05.09 — 8 сессий, 7 остановок, из них 4 предвидимые и все — денежные промахи тимлида; 06.09 (полдень) — 1 сессия, 1 остановка, предвидимая и снова денежная: рулинг тимлида разошёлся со стоящим PROCESS.md по тому, КОГДА берётся якорь линии. Ответом стали не новые правила по одному, а дефолты: `PROCESS.md` «Деньги» v2.1, PHASE v10–v14, скилл v3.5–v3.11, седьмой дефолт шаблона. Слабое место системы сегодня — именно денежная механика при смене железа и линий; сильное — ни одного доллара не потеряно без имени и ни одного числа, взятого из прозы.

## 8. Где что живёт

- **Машина оператора, `Projects/<проект>/`** — мир исполнителя: репо с `CLAUDE.md`, `.claude/`, `knowledge/`, `docs/`, `results/`. Скилл `brain-init` — в Claude Code (слэш-команда), его дельты M6 v2 — в проекте Claude.
- **Аккаунт Claude** — карточка скилла `team-lead` (текущая версия видна в списке скиллов Cowork-сессии).
- **Проект Claude (проектная память тимлида)** — память между сессиями: хэндоффы (один живой, переписывается), драфты скилла, дельты brain-init, кодбук и инструменты разметки, этот документ.
- **Cowork-сессия тимлида** — репо смонтировано read/write; правила: только `git --no-optional-locks …` (обычный `git status` оставляет lock, который VM не может удалить), файлы тимлида правятся на монтировании и **коммитятся исполнителем по пути** в ритуале старта; свежий верификатор (субагент) дотягивается до монтирования read-only. Когда папка не подключена, репо достижимо через локальный MCP Desktop Commander (чтение, `git --no-optional-locks`, листинги платформы, точечные правки) — так прошла сессия 06.09.
- **Публичный репо `two-tier-dev`** — канонический экземпляр системы: карточка скилла, этот документ, шаблоны (PHASE с семью дефолтами денег, PROCESS, PROGRESS, STATUS, ранбук платного рана, рулинги, разбор остановок), executor-kit; CHANGELOG — чему научилась каждая версия и какая остановка её научила.

## 9. Состояние на 06.09.2026 и долги системы

- **Работает:** двухуровневый цикл с одним пунктом за сессию; каталог развилок; приёмка по result-файлам; предрегистрация и один выстрел; разборы остановок с обратной связью в правила в тот же день; STATUS с датой финиша; верификатор до покупки.
- **Долги (названы, не построены):** `brain-init` M6 v2 не применён в живом репо; раздел «Деньги» шаблона файла фазы с **семью дефолтами** (линия на ран · ставка целого рана · кап из пробного расчёта · гард с линией · пост-рановое чтение как ссылка закрытия · железо и цена как поля записи · регистрация открывает линию внутри платной сессии) — в `templates/PHASE.md` §6 есть, генератор brain-init их ещё не эмитит; сбор метрик ретро из `class:` в PROGRESS, а не по памяти; один рулинг вышел за 12 строк — признак, что дефолтов ещё не хватает; оператор — единственный канал между уровнями (утомление, задержки).
- **Спекулятивно, на потом:** автоматический канал Cowork ↔ Claude Code (передача промта и отчёта без ручного копирования) и запуск платных сессий по расписанию — только после того, как денежные дефолты перестанут давать остановки.

## 10. Как запустить новый проект по этой системе

1. Новая папка в `Projects/`; в Claude Code — `/brain-init` с модулем M6 «two-tier» (CLAUDE.md, deny-правила, хуки, команды, `knowledge/`, шаблоны PHASE/PROGRESS, стандартный промт).
2. Cowork-сессия с `/team-lead`: интервью по одному вопросу (цель · метрика · реальность данных · жёсткие запреты · blindspot-проход) → `docs/PRODUCT.md` / `docs/SPEC*.md` → `docs/PHASE-<фаза>-1.md` с каталогом развилок и дефолтами «Денег» ещё до первого пункта.
3. `docs/PROCESS.md`: механика платформы (команды гарда, леджеры, пины, печати, языки) — всё конкретное, чего нет в скилле.
4. Эталон и грейдер до любой оптимизации: печатают число за $0.
5. Первая сессия исполнителя по стандартному промту ($0-скаффолдинг); дальше — каденция §4, STATUS отвечает, когда конец.
