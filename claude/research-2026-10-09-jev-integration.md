## 0. Вердикт

1. **Jev — не «ещё одна модель», а калиброванный классификатор.** Он отвечает на типизированные вопросы вероятностями за ~0,1–0,5 с и центы, не пишет текст и не вызывает инструменты. Место ему — там, где у нас сегодня либо проза («чек без вывода не пройден»), либо дорогой агент на вопрос, на который хватает «да/нет по документу». Там, где нужно воспроизвести дефект или рассудить, он слабее фронтира (vals.ai: последнее место из 12 на LegalBench) — судья `/verify-phase` остаётся Opus.
2. **Из восьми инструментов видео в базовый набор исполнителя не идёт ни один как есть.** Два дают реальный механизм для кита после калибровки — **Abide** (правила CLAUDE.md и инварианты SPEC §3 как проверка каждой правки) и идея **Belay** (Stop-hook против «готово» без доказательства). Два — по задаче: **Jev Browser** (UI-чеки фаз с веб-страницей) и **Quicksilver** (корпус больше grep-удобного, то же правило, что у Graphify). **Jev SEO** — инструмент тимлида и модуля WEB. **Toolgate** нужен не исполнителю (у него auto mode + deny + kill-switch), а сессиям оператора в `bypassPermissions`. **Steer-or-Queue** и **Compact Adviser** — опционально, в теневом режиме.
3. **`/goal` остаётся.** Ни один инструмент видео не проверяет «все фичи SPEC закрыты»: Belay смотрит лишь «заявил готово, а прогона чека нет», и не видит работу агентов воркфлоу — а под ultracode чеки гоняют именно они. Верный ответ — **двойной затвор**: `/goal` ведёт цикл (официальный, с вердиктом «невозможно», чек-инами и auto mode), а свой Stop-hook кита **`spec-gate`** проверяет конец хода по файлам — кодом (маркеры evidence по каждой фиче SPEC §2, push, голова PROGRESS) и Jev (нечёткие вопросы: заявлено «готово»? evidence противоречит «готово»? стоп — одна из четырёх причин?). Это закрывает единственную дыру нашей приёмки: оценщик `/goal` видит только разговор.
4. **Десктоп (Cowork, тимлид).** Из VM Cowork `api.typesafe.ai` не достижим (замер 09.10: HTTP 000, egress-allowlist) — Jev тимлиду доступен только на Mac: тем же `bin/jev` кита через Desktop Commander или MCP-сервером в Claude Desktop. Ценность для тимлида — проверка утверждений исследований (бриф Grok-команды, выжимки интервью) против источников и экран prompt-injection во внешнем тексте; в приёмку Jev заходит через `spec-gate` исполнителя, не вместо `/verify-phase`.
5. **Сравнение с практиками** (§7): ядро системы совпадает с официальной страницей best practices («дай Claude проверку: условие `/goal`, Stop-hook как детерминированный гейт, верифицирующий субагент/воркфлоу») — после v3.1 у нас есть `/goal` и `/verify-phase`; единственный слой, которого нет, — Stop-hook-гейт конца хода. Jev делает его дешёвым и закрывает зазор между `/goal` (видит транскрипт) и `/verify-phase` (видит клон, но через часы). Планки ретро 06.10 по скиллу, `Read first`, блокирующим и времени приёмки выполнены в v3/v3.1; «стопов на фазу» и «правки продукта ≥ правок по ревью» меряются на telefon.
6. **Как вводить:** по правилу поля харнеса — официальный источник, контрольный прогон до и после, теневой режим перед активным, код мода прочитан (`claude plugin validate`), ключ вне репо. Одна фаза кита **v3.2 «Jev-слой»** (фронтир — §8), потом одна фаза telefon в тени, активация на ретро по заранее названным планкам (§8.5).

### 2.1 Подробности по каждому (установка, цифры демо, оговорки)

**Toolgate.** `npm install -g @riskaverse/toolgate` (не `npx` — одноимённый чужой пакет), `export AI_GATEWAY_API_KEY=…`, `toolgate init` → запись `PreToolUse` в `~/.claude/settings.json` с таймаутом 10 с. Политика `~/.toolgate/toolgate.yaml` (из проекта не читается — это защита), `fail_mode: passthrough` по умолчанию: без ответа модели — обычный permission-flow; внутренняя ошибка → `ask`. Аудит `~/.toolgate/audit.jsonl`. Демо: задача «удалить папку, переложив файлы» — Claude начал удалять до копирования, destructive 77 %; в bypass-режиме Toolgate заблокировал, Claude сначала скопировал. Автор: «удаления, которые были нужны, тоже блокировал». Для нашего исполнителя смысла мало: auto mode уже классифицирует каждое действие с чтением CLAUDE.md, deny держит файлы тимлида, `kill-switch.sh` и `refuse_sweeping_commands.py` — остальное. Для сессий оператора (`defaultMode: bypassPermissions` в `~/.claude/settings.json` с 09.09) — ровно сценарий видео.

**Abide.** `npx @coldtea/abide login` (ключ TypeSafe или Vercel), `npx @coldtea/abide init [claude] [--project]`. Первый ход агента компилирует инструкции в `.abide/rubric.json` (коммитится, каждое правило цитирует строку источника; у правила `edit`/`turn` и `scope` из глобов). Демо: 49 правил, 33 требуют Jev. Цена ~$0,00004–0,00007 за проверку 13 правил, ~1 с на хук, ход из 15 правок — десятая цента; бенчмарк автора: 1 из 13 ходов в 93 сессиях ломал правило. Хуки всегда exit 0 — Abide **не блокирует**, а кладёт агенту требование починить. Для нас это механизм, которого не хватало ретро 06.10 п. 3 («правила в прозе»): инварианты SPEC §3 («секреты не печатаются», «чек возвращает среду», «evidence обезличен») становятся проверкой каждой правки. Условия входа: `abide calibrate` на истории telefon до включения; рубрика компилируется шагом 0 фазы и принимается вместе с PLAN; после приёмки `.abide/rubric.json` — файл тимлида (owner в `budgets.json`, deny `Edit`), иначе исполнитель может ослабить правило себе же.

**Jev Browser.** `npx playwright install chromium`, затем MCP-строка выше; `JEV_BROWSER_HEADED=1`, `JEV_BROWSER_PROFILE`, `JEV_BROWSER_LOG=1`. Инструменты: `browser_open / do / check / choose / snapshot / act / screenshot / close`; статусы `likely_done / needs_confirmation / ambiguous / stuck` — «проверь, не повторяй». Есть CLI `run <flow.json>` — это то, что нужно чеку фазы: детерминированный сценарий → маркер в `docs/evidence/`, без MCP в сессии исполнителя. Демо: тест страницы ~2 мин, отчёт с найденными багами. Для telefon: страница с кнопкой звонка (артефакт фазы 1), панель Command Center, модуль WEB витрины. По нашему правилу MCP ставится строкой Environment под названный чек и убирается, когда фаза его не называет; CLI-форма предпочтительнее (чек гоняется и в `/verify-phase`, и в CI).

**Jev Belay.** Плагин: `/plugin marketplace add valentynkit/jev-belay` → `/plugin install jev-belay@jev-belay`; `.env` с `TYPESAFE_API_KEY`; порог `JEV_BELAY_THRESHOLD` (в видео 75 %), лог `JEV_BELAY_LOG=1`, `JEV_MODEL=jev-1.13.0`; Node 20+, Claude Code ≥ 2.1.196. Логика: сначала бесплатная локальная проверка транскрипта (была ли команда теста/сборки/линта и сводка раннера после последней правки) — Jev вызывается лишь когда файлы менялись и чека не было (16,6 % стопов в корпусе автора); в TypeSafe уходят только промпт, финальное сообщение и два счётчика. Почему не как есть: (а) наши чеки — `bin/check-*` с маркерами `F<n>_OK`, Belay их раннером не считает; (б) «работа субагентов невидима — отдельный транскрипт», а под ultracode чеки гоняют агенты воркфлоу; (в) сам автор: «эффективность вопросов Jev пока не доказана… запускать с логом и смотреть, что бы он блокировал». Берём архитектуру (локальная проверка → Jev только на спорном → exit 2 с причиной → капы 1/промпт, 60 с, 3/сессию → fail-open) и строим `spec-gate` по нашим файлам (§5).

**Jev Steer-or-Queue.** `/plugin marketplace add Larkspur-Wang/Jev_steer_or_queue` → `/plugin install jev-steer-or-queue@jev-steer-or-queue`; ключ в keychain или `TYPESAFE_API_KEY`; `shadow` (по умолчанию, только лог) → `active` через `/config`; таймаут 2 с, fail-open на steer. Демо: смена цветовой темы во время сборки лендинга ушла как interrupt. У исполнителя оператор посреди хода не пишет — заметка идёт строкой `STEER.md` через `steer.sh`; плагин — только для собственных сессий оператора, если захочет.

**Compact Adviser.** Для Claude Code: marketplace + `compact-adviser@compact-adviser`, Node 22+, Claude Code ≥ 2.1.274, `/compact-adviser` для ключа и режима; `status / snooze / dismiss / threshold`. ## 3. Официальные механизмы Claude Code на 09.10.2026, через которые всё стыкуется

Сверено субагентом по code.claude.com (пересказ WebFetch; несущие поля перед записью в кит — контрольным прогоном, как в v3.1).

- **Хуки** ([hooks](https://code.claude.com/docs/en/hooks)): 33 события. Для нас: `PreToolUse` (`hookSpecificOutput.permissionDecision: allow|deny|ask|defer`, `updatedInput`), `Stop` и `SubagentStop` (exit 2 блокирует конец хода, причина — stderr или `reason`; вход несёт `stop_hook_active`, чтобы хук не зациклил сам себя), `PostToolUse` (не блокирует, может подменить вывод), `UserPromptSubmit`, `PreCompact` (блокирует), `TaskCompleted`/`TeammateIdle` (`continue: false`). Типы обработчиков: `command`, `http`, `mcp_tool`, **`prompt` (с полем `model`)** и `agent` (экспериментальный). Таймауты: 600 с command по умолчанию, 30 с на `UserPromptSubmit`; истёкший `PreToolUse` **не блокирует**. `allow` хука не перекрывает `deny`-правило; exit 2 бьёт раньше правил. Вход хука в субагенте несёт `agent_id` (мы на это уже опираемся в `steer.sh`).
- **Моды** ([mods/overview](https://code.claude.com/docs/en/plugins/mods/overview)): «функциональные хуки» стали официальными: плагин с JS/TS-обработчиками (`on('tool.call' | 'tool.check' | 'prompt.submit' | 'turn.complete' | 'classic.Stop' …)`), внутри процесса Claude Code; включены по умолчанию с v2.1.287 (терминал) и v2.1.286 (Desktop, вкладка Code); `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` игнорируется — README Compact Adviser устарел. Мод не в песочнице: «читает ваши секреты, видит каждый промпт, может одобрить вызов, который ваш `PreToolUse`-хук заблокировал». Перед установкой — `claude plugin validate ./мод` (строки `hooks:` и `calls:`). Работают и в `claude -p` (без отрисовки). Выключить все — `--safe-mode` на сессию или `disableAllHooks`.
- **`/goal`** ([goal](https://code.claude.com/docs/en/goal)): один goal на сессию, ≤ 4000 знаков; «сессионный prompt-Stop-hook»: после каждого хода малая быстрая модель судит условие **только по разговору** — инструментов не запускает, файлы не читает; вердикты «не выполнено / выполнено / невозможно»; лимит ходов пишется в условие; фоновая работа откладывает оценку; чек-ины с 30 мин (`CLAUDE_CODE_GOAL_CHECKIN_MINUTES`); неинтерактивно — `claude -p "/goal …"`; для безнадзорного прогона — вместе с auto mode; недоступен при `disableAllHooks`.
- **Воркфлоу / ultracode** ([workflows](https://code.claude.com/docs/en/workflows)) — как в `claude/ultracode-2026-10-07.md`; `Workflow(<имя>)` в allow; в `-p` ключевое слово не работает. Важно для Jev-хуков: под ultracode чеки гоняют агенты в своих worktree, а их транскрипты — отдельные.
- **Плагины**: `/plugin marketplace add <owner/repo>`, `/plugin install <plugin>@<marketplace>` (scope user/project/local), `/reload-plugins`; `claude plugin eval` (v2.1.269+, грейдеры `regex / tool_used / file_exists / llm / baseline`) — это и есть официальный способ **абляции** правил скилла, которую требует §8.
- **Best practices** ([best-practices](https://code.claude.com/docs/en/best-practices)): «дай Claude проверку, которую он может запустить: условие `/goal`, Stop-hook как детерминированный гейт, верифицирующий субагент или воркфлоу»; интервью через `AskUserQuestion` → `SPEC.md` → свежая сессия; ревьюер в свежем контексте «перечисляет находки даже у здоровой работы — просить только дефекты корректности и пробелы требований»; auto mode — стартовый режим с v2.1.283. Про «spec-driven development» как термин — официальной страницы нет; наш цикл ему соответствует через интервью → SPEC → `/goal`.

## 4. Где Jev сильнее и слабее наших сегодняшних судей

| Судья | Что видит | Цена / время | Сильная сторона | Слабая сторона |
|---|---|---|---|---|
| Оценщик `/goal` (малая модель) | только разговор | подписка, секунды | официальный цикл, «невозможно», чек-ины | не читает файлы; компакция стирает маркеры |
| Классификатор auto mode | каждый вызов инструмента, CLAUDE.md, `autoMode.environment` | подписка | нативный, знает доверенную инфраструктуру | блоки на законные действия («Authorized in this goal») |
| `prompt`-хук с `model: haiku` | вход хука + промпт | подписка, 2–5 с | рассуждает, текстовая причина | не калиброван, медленнее, дороже на тысячах вызовов |
| `/verify-phase` (Sonnet + Opus, свежий клон) | клон, инструменты, воспроизведение | 7–30 мин, ~11 агентов | воспроизводит, мутирует, судит | дорого на каждый ход; только на приёмке |
| **Jev в хуке/скрипте** | ровно то, что передал скрипт (state ≤ 64 K) | $0,00002–0,0001, 0,1–0,5 с | калиброванная вероятность, десятки вопросов за один вызов, можно звать на каждом ходе и каждой правке | не читает файлы сам, не воспроизводит, не рассуждает; порог надо ставить на своих метках |

Правило, которое из этого следует и которое пойдёт строкой в скилл (§8.4): **ограниченный документный вопрос — Jev; вопрос, требующий воспроизведения или синтеза, — свежий агент.** Jev не заменяет судью `/verify-phase`, а дополняет цикл исполнителя там, где агента на каждый ход не позовёшь.

## 5. Вопрос `/goal`: нужен ли он, если Jev проверит спеку

**Что проверяет `/goal` сегодня.** Условие — наш `docs/GOAL.txt` (END STATE A/B/C + ограничения); оценщик читает транскрипт и верит тому, что исполнитель напечатал; поэтому у нас правило «последний ход — одна команда гейта печатает все маркеры». Файлы `docs/evidence/`, push ветки и голову PROGRESS он не открывает — это проверяет уже `/verify-phase` на приёмке, через часы.

**Что из видео проверяет «все шаги спеки выполнены».** Ничего напрямую:
- Belay отвечает на «заявил готово, а чека не было» — по транскрипту одного хода, без файлов, без субагентов;
- Abide — «правка нарушает правило из CLAUDE.md» — инварианты, не полноту фазы;
- `jev_gate` из jev-mcp — «дифф + заявления против переданного evidence» — только если кто-то вызовет его и передаст evidence; сам он ничего не гейтит.

Проверка «каждая фича SPEC §2 закрыта» на 90 % детерминирована (файл evidence с маркером, зелёный rc, ветка запушена, VERDICT PASS для HEAD) — ей не нужна модель. Нечёткие 10 % — «финальное сообщение заявляет завершение фазы?», «голова PROGRESS называет что сделано, следующий шаг оператора и когда?», «строка STOP ссылается на одну из четырёх причин и несёт resume-строку?», «текст evidence противоречит формулировке «готово» фичи?» — это ровно ограниченные документные вопросы, где Jev в шуме фронтира за центы.

**Три варианта.**

| Вариант | Что происходит | Плюсы | Минусы |
|---|---|---|---|
| **A. `/goal` + `spec-gate` Stop-hook (рекомендую)** | `/goal` ведёт цикл; Stop-hook кита на каждом конце хода: код проверяет файлы, Jev — нечёткое; несогласие → exit 2 с причиной «не хватает маркеров F3, F5; PROGRESS без даты» | официальный цикл сохраняется (вердикт «невозможно», чек-ины, auto mode, откладывание на фоновую работу); реальный гейт — по файлам, а не по словам; работает и под ultracode (хук читает `docs/evidence/`, написанные агентами) | +1 хук в харнесе; калибровка порогов на своих стопах; капы против зацикливания (как у Belay: 1/промпт, 60 с, 3/сессию) |
| B. Только Stop-hook, без `/goal` (Ralph-loop) | хук держит сессию, пока предикат не выполнен | не нужен ручной `/goal`; нет лимита 4000 знаков | теряем «невозможно», чек-ины, откладывание на фон, официальную поддержку; свой цикл = свой оркестратор, что INTENT N2 запрещает |
| C. Статус-кво: только `/goal` | как сейчас | ничего не меняется | дыра между «сказал» и «сделал» закрыта только приёмкой через часы; это и есть главный зазор против best practices («Stop-hook как детерминированный гейт») |

**Ответ оператору:** `/goal` остаётся — он единственный официальный драйвер безнадзорного цикла, и писать его дешево (≤ 4000 знаков, по шаблону). Jev делает `/goal` **честным**: оценщик верит словам, `spec-gate` — файлам. После этого END STATE в GOAL можно укоротить: перечень доказательств остаётся в коде хука, в предикате — одна строка «spec-gate печатает SPEC_GATE_OK».

**Побочный выигрыш — ручной ввод `/goal`.** Документация подтверждает `claude -p "/goal …"`; интерактивный запуск с goal в стартовом промпте (`claude "/goal $(cat docs/GOAL.txt)"`) не описан — проверить одним контрольным прогоном; если работает, строка запуска в `docs/PROCESS.md` стартует фазу без ручного набора, а `SessionStart`-хук (`initialUserMessage`) — запасной путь.

### 5.1 Эскиз `spec-gate` (для SPEC-v3.2, строится исполнителем под `/goal` с установленным скиллом `typesafe`)

- **Событие:** `Stop` (и не `SubagentStop` — агенты воркфлоу не заявляют фазу). Вход — `stop_hook_active`, `transcript_path`.
- **Ворота $0 (код, Node, без зависимостей):** нет `docs/GOAL.txt` или `SPEC_GATE=off` (ставит `bin/verify-phase` и `check-harness`) → exit 0. Читает SPEC из `Read first:` GOAL; по каждой строке `- **F<n>` ищет `docs/evidence/F<n>-*-result.txt` и маркер; `git status`/`ls-remote` — ветка запушена; голова PROGRESS изменена в этой сессии; новая строка `STOP: <id>`; `docs/evidence/verify-<sha>.txt` с `VERDICT: PASS` для HEAD. Полный комплект (A) или (B) или (C) → `SPEC_GATE_OK`, exit 0.
- **Jev (только на неполном комплекте):** один вызов, state = финальное сообщение + голова PROGRESS + список маркеров/отсутствий; вопросы `noul`: `claims_done` · `progress_head_complete` (сделано / следующий шаг оператора / когда) · `stop_cites_reason` · по фиче `evidence_contradicts_done_F<n>` (speculative fan-out). Пороги стартовые (как у Belay) `claims_done ≥ 0,75`, калибруются по логу теневой фазы.
- **Решение:** комплект неполный и `claims_done ≥ порог` → exit 2, причина = список недостающих маркеров/файлов (детерминированная, не «Jev сказал»); комплект неполный и claims_done низкий (исполнитель сам пишет «не закончил») → exit 0 — `/goal` продолжит цикл сам; таймаут 20 с и любая ошибка → exit 0 (fail-open, как у всех восьми); капы 1/промпт, 60 с, 3/сессию; каждое решение — строкой в `docs/evidence/spec-gate.jsonl` (для теневого режима `SPEC_GATE=shadow` — только строка, без exit 2).
- **Контрольные прогоны (`bin/check-harness`, пробы):** (1) фикстура с одним маркером из двух + «готово» → exit 2 с именем F; (2) полный комплект → `SPEC_GATE_OK`; (3) без ключа / с мёртвым `TYPESAFE_BASE_URL` → exit 0 за ≤ 20 с; (4) под `-p` в `bin/verify-phase` — молчит.
- **Что уходит в TypeSafe:** финальное сообщение, голова PROGRESS, имена файлов и маркеры. Не уходят: код, диффы, секреты, транскрипт.

## 6. Десктопная сторона (Cowork, тимлид): что меняется

**Факт сети (замер 09.10):** из VM Cowork `api.typesafe.ai` и `openrouter.ai` не достижимы (HTTP 000, egress-allowlist). Значит, Jev тимлиду доступен только на Mac оператора: (а) `bin/jev` кита через Desktop Commander (`start_process` в репо проекта, ключ в окружении Mac — оператор ставит сам, как делал с токеном FlashArb), (б) MCP-сервер `jev` в `claude_desktop_config.json` (jev-mcp, 12 инструментов). Порядок: сначала (а) — одна реализация на оба яруса, свой код, пин версии, fail-open; (б) — опционально, после чтения исходника, ради готовых `jev_verify`/`jev_screen`.

**Где Jev меняет работу тимлида (патерны, не правила):**
1. **Исследования и внешний текст.** Брифы Grok-команды, выжимки интервью, сторонние страницы: `jev_verify` (каждое утверждение против цитируемого источника — та самая «bounded verification», где Jev на уровне фронтира) и `jev_screen` (prompt-injection в полученном тексте — наш «Instruction source boundary» механизмом). Это ускоряет такт Grok-команды и грилинг: не «прочитать и поверить», а «проверено, X из Y утверждений не находят источника».
2. **Приёмка.** Без изменений в `/verify-phase`; Jev заходит через `spec-gate` исполнителя. Своё чтение тимлида может использовать `bin/jev` на вопрос «evidence противоречит «готово»?» по каждой фиче — те же вопросы, что в хуке, тот же файл вопросов (единый источник).
3. **Грилинг.** Не меняется: таблица посадки — арифметика, не суждение. `check-budget` уже держит форму строки фичи.
4. **Модуль WEB / витрина.** `jev-seo` — отчёт тимлида заказчику (PDF + XLSX) и чек фазы WEB («балл ≥ N, 0 блокирующих действий» → маркер).

**Скиллы Cowork (team-lead v6 ≤ 80 строк, «одно вошло — одно вышло»; grilling без изменений).** Предложение на ретро v3.2, не раньше:
- §6 Приёмка, **входит:** «Повторяемый нечёткий вопрос конца хода (заявлено «готово»? evidence противоречит «готово»? стоп по одной из четырёх причин?) — калиброванному классификатору хуком за центы, вопросы и пороги в одном файле репо; воспроизведение и синтез — свежему агенту, не классификатору».
- §8 Харнес, **входит:** «Сторонний хук, мод или MCP ставится как поле харнеса: источник, `claude plugin validate`, ключ вне репо, теневой режим с логом до активного, контрольный прогон до и после».
- §8, **выходит:** строка «`ultracode` — ключевым словом на параллельные задачи» (уже устарела после v3.1: ultracode — штатный режим, `--effort ultracode` в строке запуска).
- Вторая «выходит» — на ретро по абляции (`claude plugin eval` на кейсах `claude/evals-2026-10-06/`).

**Вкладка Code в Claude Desktop.** Моды и хуки там работают (Desktop ≥ 2.1.286), так что кит одинаково ведёт себя в терминале и в Desktop; наша пара контрольных прогонов остаётся на `claude -p`.

### 8.1 Фичи (кандидаты в SPEC-v3.2 §2; формулировки «готово» — на грилинге)

Служит обоим ярусам.

### 8.2 Порядок
1. Оператор: ключ TypeSafe (или Vercel AI Gateway — он единственный общий для Toolgate/Abide/jev-mcp; у Belay/Browser/SEO/Quicksilver — только TypeSafe) → в env Mac, не в репо. Проверка доступа — один `curl` с `state: "ping"` и одним `noul`.
2. Грилинг v3.2 по §9 → SPEC-v3.2 → `/goal` исполнителю (ultracode, как v3.1) → `/verify-phase` → гейт оператора.
3. Перевод telefon на v3.2 с `SPEC_GATE=shadow`, Abide в режиме «заметка» (0,5–0,8) на одно плечо → ретро: лог решений против фактических стопов/приёмок → пороги → `active`.
4. Ретро v3.2: две строки в скилл (§6), абляция через `claude plugin eval`.

### 8.3 Что меняется в принципах работы (патерны)
- **Три судьи по стоимости вопроса:** код — где можно grep; Jev — где вопрос ограничен документом и повторяется на каждом ходе/правке; свежий агент — где нужно воспроизвести или синтезировать.
- **Сказал ≠ сделал — проверяется на каждом конце хода**, а не только на приёмке.
- **Сторонний хук/мод — поле харнеса**, не плагин «поставил и забыл»: источник, validate, ключ вне репо, тень → актив, прогон до/после; инертный — удаляется.
- **Правило в прозе, которое можно задать как вопрос к диффу, — правило Abide**; правило, которое можно задать как grep, — чек.

### 8.4 Риски и ограничения
- **Данные к американскому вендору.** TypeSafe получает: Abide — изменённые строки; `spec-gate` — финальное сообщение и голову PROGRESS; Quicksilver — содержимое файлов; Compact Adviser — выдержки из ответов и результатов инструментов. Ограничение telefon «никаких американцев» относится к цепочке продукта (кто получает данные звонящих или деньги) — dev-инструменты в неё не входят (как и сам Claude Code). Условие: в файлах, которые читают хуки, нет реальных данных звонящих — витрина `demo-01` синтетическая, транскрипты реальных звонков (фаза 3) в репо не попадают. Решение оператора — §9 в1. Через Vercel AI Gateway есть `zeroDataRetention`; про обучение на данных клиентов TypeSafe заявляет «нет» (по README Quicksilver, первоисточник не найден — проверить на консоли).
- **Зрелость.** Все восемь — сообщество, 0–4 недели от роду; README Belay и Steer-or-Queue сами требуют теневой режим. Пины версий, свой форк не нужен — `bin/jev`+`spec-gate` свои.
- **Моды видят секреты и могут одобрить заблокированный вызов** (официальная страница). Compact Adviser — мод: `claude plugin validate` до установки, список `calls:` в CHANGELOG.
- **Ultracode:** транскрипты агентов отдельные — любой Stop-хук «по транскрипту» (Belay) слеп; `spec-gate` читает файлы, поэтому и выбран.
- **Калибровка не переносится** (vals.ai): пороги `spec-gate`/Abide — только по нашему логу; стартовые — из README авторов.
- **`-p`:** хуки и моды работают, Compact Adviser молчит, ключевое слово ultracode не работает; `bin/verify-phase` ставит `SPEC_GATE=off`, чтобы гейт не держал приёмочную сессию.
- **Лимиты и `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`** — глушит сетевые запросы Compact Adviser; у нас не стоит, но знать.

### 10.2 Фаза без `/goal` — как это работает механикой
1. **Запуск.** Строка запуска PROCESS получает стартовый промпт аргументом: `claude … "$(cat docs/PROMPT.txt)"` (интерактивная сессия со стартовым запросом — cli-reference; ручного набора нет). `docs/PROMPT.txt` ≤ 5 строк: «Фаза n по `docs/SPEC-n.md`. Сделано = `bin/gate-n` печатает все маркеры и `/verify-phase` PASS. Стоп — только по SPEC §4 строкой `STOP:`». `docs/GOAL.txt`, шаблон GOAL и бюджет `goal_chars` уходят; END STATE живёт в SPEC §5 (артефакт закрытия + команда гейта).
2. **Цикл.** `spec-gate` (Stop-hook, §5.1) в активном режиме: конец хода блокируется (exit 2), пока у фич SPEC §2 нет evidence с маркером, ветка не запушена или голова PROGRESS не обновлена — причина перечисляет недостающее; новая строка `STOP: <id>` по §4 или `SPEC_GATE_OK` — ход заканчивается. Это тот же механизм, которым документация описывает сам `/goal` («session-scoped prompt-based Stop hook»), уровнем ниже и по файлам, а не по разговору; не оркестратор (INTENT N2).
3. **Предохранители вместо страховок `/goal`.** «невозможно» → `STOP-SCOPE`; лимит блоков на сессию (стартово 12) и время (3 ч) → хук пропускает с причиной «cap», чекпоинт в PROGRESS; `stop_hook_active` — не блокировать повторно подряд; `AGENT_STOP` — kill-switch; ошибка/таймаут Jev → fail-open.
4. **Второй судья для сравнения.** Belay в тени (лог) на том же плече: на ретро видно, где два хука разошлись.
5. **Абляция (§8 скилла).** Первое плечо кита v3.2 строится уже без `/goal`; планки — §8.5 плюс «ходов с блоком `spec-gate` на плечо» и «ложных блоков ≤ 1».
