# Ultracode по полной — изучение и решения (тимлид, 07.10.2026)

Решение оператора 07.10: «изучи все его возможности и давай использовать его по полной». Факты — из официальных источников для Claude Code 2.1.292: сырые страницы `code.claude.com/docs/en/<page>.md`, CHANGELOG Claude Code, пост Anthropic «Introducing dynamic workflows» (28.05.2026). Пересказ WebFetch длинной страницы однажды выдумал переменную `CLAUDE_CODE_DISABLE_ULTRACODE` — её нет. Поэтому несущие факты ниже сверены по сырому `.md`.

## 1. Что умеет
- **Ultracode.** Claude сам планирует воркфлоу на каждую существенную задачу (workflows). По посту Anthropic: «checking its work before anything reaches you». Цена — «substantially more tokens».
- **Включение.**
  - `--effort ultracode` — сессия с ultracode на `xhigh` (v2.1.203+).
  - Ключ `"ultracode": true` — сессии стартуют с ultracode; `/effort ultracode off` выключает его на одну сессию.
  - `/effort ultracode` — на текущую сессию.
  - С 2.1.284 ultracode — отдельный тумблер, уровень effort он не меняет. Нужна модель с `xhigh`; у Opus 5.5 он есть.
  - Проверено на Mac 07.10: с `--effort ultracode` баннер пишет «Opus 5.5 with xhigh effort», маскот фиолетовый (RGB 175,135,255). Без ultracode маскот оранжевый (215,119,87).
- **Воркфлоу.** Это JS-скрипт.
  - Примитивы: `agent()`, `pipeline()`, `parallel()`, `phase()`, `log()`, `args`, `meta`.
  - С `schema` агент отвечает JSON. Модель задаётся на каждого агента.
  - `Date.now()` и `Math.random()` запрещены, поэтому прогон воспроизводим и возобновляем.
  - Лимиты: 16 агентов одновременно (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`, до 256), 4 096 элементов на вызов, 1 000 агентов на прогон.
  - Сам скрипт не трогает файлы и shell — это делают агенты. В разговор сессии возвращается только итог.
- **Сохранённые воркфлоу.** Лежат в `.claude/workflows/` проекта (идут вместе с репо и вызываются командой `/<имя>`), в `~/.claude/workflows/` или в плагинах. Справочник и паттерны качества — встроенный скилл `/workflow-authoring`.
- **Управление.** `/workflows`: пауза `p`, стоп `x`, рестарт `r`, сохранить `s`. В интерактивной сессии на подписке прогон, упёршийся в лимит, ждёт сброса (`autoContinueAtUsageLimit`, по умолчанию включено).
- **Расходы.**
  - `workflowSizeGuideline` — совет модели, а не потолок: `small` <5, `medium` <10 (дефолт Max), `large` <50, `unrestricted`.
  - Под ultracode скрыто предупреждение «Large workflow» и не действует лимит в 20 параллельных сабагентов. Лимиты подписки кончаются раньше.
- **Паттерны качества** (пост, docs):
  - независимая проверка находок;
  - агенты, которые пытаются сломать результат;
  - независимые попытки со сходимостью;
  - план с нескольких углов;
  - «чини, пока чек не зелёный; стоп после двух раундов без прогресса».
- **`claude -p`.** Ключевое слово `ultracode` там не работает. Сохранённый воркфлоу разрешается правилом `Workflow(<имя>)`. `-p` ждёт фоновую работу до 10 минут простоя.

## 2. Стыковка с механикой кита
| Механизм | Факт | Что делаем |
|---|---|---|
| auto mode | Агенты проверяются классификатором при запуске, на каждом действии и на отчёте. Промпт `agent()` не считается просьбой оператора. Узкие allow-правила срабатывают раньше классификатора. После 3 блоков подряд или 20 всего auto mode переходит на вопросы (permission-modes). | Узкие `permissions.allow` на чеки кита и фазы — механизм вместо строки «Authorized in this goal» |
| push в `main` | Auto mode по умолчанию разрешает push в любую ветку своего репо, включая ветку по умолчанию. Классификатор читает CLAUDE.md проекта (auto-mode-config). | В `kit/CLAUDE.md` строка «push в main запрещён: main меняет только оператор» — её читает и классификатор. Плюс защита `main` на GitHub (сейчас не включена). |
| deny `Edit` | Вызовы агентов проходят те же проверки (workflows, sub-agents) | Контрольный прогон: агент воркфлоу правит файл тимлида → отказ |
| PreToolUse-хуки | Срабатывают и в сабагентах; `agent_id` во входе есть только у сабагента (hooks) | `steer.sh` отдаёт заметку только главной сессии: сейчас он чистит `STEER.md` после первой доставки, и заметку перехватит первый попавшийся агент. Для `kill-switch.sh` прогоном доказать, что `AGENT_STOP` останавливает и агентов. |
| worktree | Worktree сабагента по умолчанию ветвится от ветки по умолчанию репо (worktrees) | `worktree.baseRef: "head"` |
| `/goal` | Пока работает сабагент или фоновая команда, оценка откладывается; оценщик видит только разговор (goal) | Правило «последний ход — одна команда гейта печатает все маркеры» остаётся; evidence пишут агенты в файлы |
| `check-harness` | Контрольные `claude -p` берут строку запуска из `docs/LAUNCH.md` | Пара остаётся детерминированной и со строкой `--effort ultracode` |

## 3. Решения оператора 07.10
1. Ultracode включается строкой запуска исполнителя: `--effort ultracode` (xhigh + ultracode) в `docs/LAUNCH.md`. Сессии оператора в проекте идут без него; max — по желанию на сессию.
2. `workflowSizeGuideline: "medium"` (до 10 агентов) вместо `small`. Фаза с широким веером поднимает размер в своём GOAL.
3. Бюджет лимитов подписки на фазу исполнителя — 15 % недели; `/usage` после плеча записывается в STATUS. Превышение разбираем на ретро, ultracode сгоряча не отключаем.
4. Свежая проверка на приёмке — сохранённый воркфлоу `/verify-phase`: параллельные состязательные проверяющие по фичам плюс судья. Запуск из свежего клона через `claude -p`, с лимитом времени. Цель — приёмка не дольше плеча (06.10 было 4 ч против 1 ч).

## 4. Фаза v3.1 «ultracode по полной» — фронтир для SPEC
Один SPEC, один `/goal`; исполнитель сам работает под ultracode.
1. Харнес: `worktree.baseRef: "head"`, `workflowSizeGuideline: "medium"`, узкие allow на `bin/check-*`, `bin/gate-*`, `make ci`. Строка запуска в `docs/LAUNCH.md` — `--effort ultracode`.
2. Хуки: steer отдаёт заметку только главной сессии; kill-switch и deny делом проверены на агентах воркфлоу.
3. `kit/.claude/workflows/verify-phase.js`. По каждой фиче SPEC: свежий прогон её чека, поиск пограничных случаев против «готово», мутация в продукте. Судья со `schema` сводит находки (блокирующих не больше 5) в `docs/evidence/verify-<sha>.txt`. Красная сторона: на фикстуре с подложенным пограничным дефектом воркфлоу его находит. Зелёная: на чистой фикстуре молчит.
4. `kit/.claude/workflows/fix-until-green.js`: чек → правка → чек; стоп после двух раундов без прогресса (STOP-NP).
5. `/accept`: вердикт выносит `/verify-phase` в свежем `claude -p` (`Workflow(verify-phase)`) с лимитом времени. Приёмка тимлида — тот же воркфлоу из свежего клона.
6. Шаблоны:
   - GOAL — перед (A) прогон `/verify-phase`, его блокирующие чинятся в той же сессии;
   - PROCESS — строка Environment «ultracode» и бюджет лимитов фазы;
   - `kit/CLAUDE.md` — «агенты воркфлоу правят только в своих worktree или только читают; коммит делает главная сессия, по точным путям; push в main запрещён».
7. Документы: CHANGELOG (у каждого поля — ссылка на док и прогон до/после), `docs/LAUNCH.md`, OFFICIAL-SOURCES (тимлид).
8. INTENT: N2 → «своего оркестратора не строим; воркфлоу — штатный режим исполнителя (ultracode)». Строка в журнал 07.10. Новый пин — в коммите SPEC-v3.1: раньше нельзя, пин SPEC-v3 покраснеет.
9. Скилл team-lead v6 §8 («`ultracode` — ключевым словом на параллельные задачи») правим после приёмки v3.1, по замеру — так требует §8 скилла.
