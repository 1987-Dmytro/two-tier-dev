# Handoff 2026-09-10c — dev-system v2: решения сессии

**Статус:** решения приняты в чате 10.09.2026 (14:00–19:00). В репо, скиллах и harness'е НИЧЕГО не менялось. ship-1 (market-pulse) у исполнителя; гейт пт 11.09 вечер, резерв сб 12.09 12:00. До гейта систему не трогаем.

## Решения (не пересматриваются в следующей сессии)

- **D1 Ретро.** Двухъярусная архитектура верна и совпадает с официальным циклом Anthropic (interview → SPEC → свежая сессия → check → adversarial review). Три отклонения: закон перерос модель (скилл 385 строк, v3.11→v3.22 за 4 дня); оператор — шина между Cowork и Claude Code (44 сессии); интеллект не с той стороны — Fable 5.1 тратился на рулинги и бухгалтерию, а не на решения (по D3 лимиты Fable не тянут исполнителя, поэтому Fable остаётся на тимлид-стороне, где он реально нужен для интервью и приёмки; код — Opus 5).
- **D2 Runtime.** Исполнение — только Claude Code. Cowork/чат — интервью, чтение STATUS/evidence, разметка данных, ретро. Не runtime тимлида на каждый айтем.
- **D3 Модель и effort (поправлено 10.09 вечером).** Исполнитель — **Opus 5.0 на effort `max`** («ultracode» — максимальный уровень effort в Claude Code; лимитов Fable на исполнителя не хватит). Fable 5.1 — только тимлид-сторона (Cowork/чат). `max` — для фазовых `/goal`-прогонов и трудной отладки/архитектуры; `maxEffortLevel: max` в settings. Рутина (миграции, чистка, кит) — `medium`/`low`: доки Opus 5 говорят использовать их широко там, где качество держится; sweep (D13) прогнать на Opus 5 заново, не переносить дефолты с Fable. Effort и правки CLAUDE.md/settings — только на старте сессии (посреди — инвалидация prompt-cache). Официальное предупреждение: `max` сжигает лимиты быстрее всего, включать по сессии — поэтому на первой неделе смотреть `/usage` после каждого фазового прогона; если недельный лимит уходит раньше пятницы, фазы опускаются на `xhigh`, а не рутина поднимается. Отката «Fable → Opus по N %» больше нет.
- **D4 Интервью живёт в Cowork** с привязанной папкой репо. Порядок нового проекта: создать репо → Cowork → привязать папку → `/team-lead` → интервью → `docs/SPEC-1.md`.
- **D5 Блок Environment в интервью** (9 вопросов: runtime и чек по типам фич; стек → диагностика CLI; доки → Context7; размер корпуса → Graphify; UI → встроенный браузер / Playwright только для evaluator'а; внешние сервисы → CLI, MCP лишь без CLI; деньги/необратимое → deny + guard + cap; effort по типам сессий и откат по лимиту; что явно НЕ ставим). Полный разбор — на kickoff, на каждой фазе — только дельта. Инструмент входит в среду только под названный чек или фичу.
- **D6 Дефолты среды.** Context7 — MCP, да. Graphify — скилл (`pip install graphifyy && graphify install`), `/graphify src --wiki`, `graphify hook install` (post-commit, AST, без LLM), `graphify claude install` (секция в CLAUDE.md, проверить размер); MCP-режим ВЫКЛ (опция для Claude Desktop на стороне тимлида); строить по `src/`, не по всему репо. Ponytail — плагин (`/plugin marketplace add DietrichGebert/ponytail`, затем `/plugin install ponytail@ponytail`, двумя сообщениями), уровень `full`; `evaluator.md` знает про лестницу (корректность против SPEC, не вкус); `/ponytail-review` — второй проход на diff; `code-simplifier` НЕ ставить. LSP — нет (диагностика через `tsc`/`pyright`/`cargo check` в чеке). Прочие MCP — нет по умолчанию; браузер встроенный; остальное CLI.
- **D7 Harness.** Официальные примитивы из `anthropics/cwc-long-running-agents` вместо brain-init M6: `agents/evaluator.md` (без Write/Edit), хуки `verify-gate` (default-FAIL: запись в `test-results.json` только после Read evidence), `commit-on-stop`, `kill-switch` (`AGENT_STOP`), `steer` (`STEER.md`). Один судья на Stop — `/goal`; второй блокирующий Stop-hook не ставить (кап 8 блоков); детерминированные защиты — PreToolUse.
- **D8 /goal.** Условие ≤4000 символов: одно измеримое конечное состояние + названный чек (команда → вывод в транскрипте) + ограничения + «stop after N turns» + стоп-точка как ВЫПОЛНЕННЫЙ goal (`STOP: <id>` в PROGRESS.md). Evaluator — Haiku, читает только транскрипт: в CLAUDE.md строка «Show the command and its output for every check; never report a check as passed without its output in the transcript». Платное плечо — всегда отдельный `/goal` после решения оператора. Условие — это директива хода: стандартный промт живёт в CLAUDE.md. **Разделение труда (уточнено 10.09 вечером):** тимлид (Fable 5.1, Cowork) описывает воркфлоу в SPEC — что должно работать, каким чеком это доказывается, инварианты и стоп-точки; исполнитель (Opus 5 на `max`) под `/goal` сам строит воркфлоу и порядок работ (PLAN, D16). Тимлид не расписывает шаги реализации.
- **D9 Строгость приёмки.** Стартуем с лёгкой: `/goal` + evaluator-сабагент по CLAUDE.md. Строгий Stop-hook с evaluator'ом — только если фичи закрываются без evidence.
- **D10 Скилл team-lead v4.** ≤80 строк, только паттерны. v3.22 → `docs/archive/`. Каждая строка v3.22 раскладывается: hook / PROCESS.md проекта / удалить (не сработала) / оставить (паттерн). §10 «каждый стоп → правило» заменён: правило добавляется только при повторе той же ошибки без него, и сначала как hook. Карту v4 показать оператору ДО записи в репо.
- **D11 Репо.** two-tier-dev v2 в существующем репо `1987-Dmytro/two-tier-dev` (не новый). Структура:
  ```
  README.md · bin/two-tier-init · kit/CLAUDE.md · kit/REVIEW.md (lite, инструкция evaluator'у)
  kit/.claude/{agents/evaluator.md, hooks/, rules/graphify.md, settings.json,
               skills/{team-lead, grilling, plan-phase, accept}}      ← skills вместо commands (D17)
  kit/docs/{SPEC,PLAN,STATUS,PROGRESS,PROCESS}.template.md · kit/intent/intent.template.md
  docs/interview.md · docs/archive/
  ```
  PROCESS-шаблон несёт Environment, Money (8 дефолтов) и каталог развилок из v3.22. `docs/archive/` — вне `kit/`, без CLAUDE.md внутри (nested CLAUDE.md подгружаются при чтении файлов в папке).
- **D12 Точки решения оператора — три:** спека (да/нет), стоп-точка (буква из таблицы решений), гейт (сам открывает продукт). Всё остальное — код, хук или evaluator.
- **D13 Метрики.** Фичи на экране в неделю по проекту; часы оператора на фичу; sweep effort (`low/medium/high` × ±Ponytail на 3 рутинных задачах, `/cost` в таблицу); `/context` и `/skill-doctor` на ретро фазы.
- **D14 Пилот.** Первый живой проект — AD Allianz (конкретный проект открыт, критерии ниже). market-pulse мигрирует после гейта первым $0-айтемом (`.claude/` рядом, старое отключаем по одному) + `/graphify src` + `/ponytail-debt`.
- **D15 Планирование (три пробела, закрыты).** (1) Граф зависимостей — две пометки на строку фичи в SPEC: `after: F2` и `[P]`; полный DAG-трекер (Beads) — не раньше 20 фич на фазу. (2) Параллелизм — по умолчанию последовательно; вторая worktree-сессия только для группы `[P]`, не трогающей общие схемы/миграции/lockfile; максимум две (потолок = способность оператора ревьюить); сабагенты — исследование и evaluator; agent teams — нет. Десятый вопрос блока Environment. (3) Шаблон SPEC-фазы, шесть секций: 0 Контекст · 1 Технический дизайн высокого уровня (без деталей реализации — ошибка в них каскадом уходит в код) · 2 Фичи (`id · user story · «готово» · команда чека · after: · [P]`) · 3 Инварианты и границы · 4 Стоп-точки · 5 Артефакт закрытия · 6 Открытые вопросы. Фича = вертикальный срез через все слои, демонстрируемый сам по себе, размером в одно свежее окно контекста (правило из `to-tickets` Покока). Шаг 0 фазы: исполнитель в plan mode читает SPEC и возвращает порядок фич, неясности и команды чеков — это и есть PLAN (D16).
- **D16 Артефактная цепочка intent → spec → plan** (источник — AI-Native SDLC playbook Anthropic, 21.08.2026; видео «Claude Code's New INTENT.MD» — его сторонний разбор). `intent/<slug>.md` (проблема · желаемый результат · затронутые пользователи и системы · ограничения · открытые вопросы) → grilling-интервью в Cowork → `docs/SPEC-n.md` (шесть секций D15) → исполнитель в plan mode → `docs/PLAN-n.md` коммитом (файлы, порядок, риски, доказательство; критерий — по плану может реализовать инженер, не видевший разговора; отклонение → обновить PLAN тем же коммитом; хук plan-sync только если увидим расхождения) → `/goal` → evaluator сверяет диф со SPEC и PLAN по `REVIEW.md`-lite (баги · безопасность · соответствие spec/plan · что считать Important). **Роли:** Дмитрий — CTO, весь технический процесс; Adrian — CCO, продажи и клиенты, в системе разработки не участвует (ни скиллов, ни Cowork, ни intent-папки), видит только выход. intent.md пишет всегда Дмитрий — обязателен, когда задача приходит извне (запрос клиента через Adrian, обратная связь Эди, инцидент); своя идея — десятистрочная шапка SPEC. **Движок интервью — `grilling`** (mattpocock/skills, MIT, `skills/productivity/grilling/SKILL.md`, семь предложений): дерево дизайна, раунды по фронтиру, нумерованные вопросы с рекомендуемым ответом на каждый, факты добывает сабагент, решения — за оператором, конец когда фронтир пуст; `grill-me` — шим для голосовой команды, опционален. Кладём копией в кит (редактируемый файл рядом с team-lead), не плагином. Весь плагин Покока (37 скиллов) не ставим; `diagnosing-bugs` прочитать построчно перед первым Maintain-циклом. Из плейбука НЕ берём: managed settings, OTel, evals в CI, Claude Security, автономный Maintain по control bands.
- **D17 Сверка кита с доками (memory, costs, Opus 5 / Fable 5.1, 10.09.2026).** Совпадает: CLAUDE.md ≤40 строк (потолок 200, плейбук — «под страницу»; только факты на каждую сессию + блок верификации «прогони, вставь вывод, чини код — не тест» + строка D8); evaluator без Write/Edit = verifier плейбука; хуки как детерминированный слой; CLI вместо MCP. Поправки: (1) `commands/` → `skills/` с `disable-model-invocation: true` (legacy-путь работает, но skills — рекомендованный); inline-bash в `/accept` для STATUS/evidence. (2) В CLAUDE.md — блоки из «Prompting Claude Opus 5» (исполнитель — Opus 5, D3): рамки «Deliver what was asked, at the scope intended … finish the whole task, stop short of actions clearly beyond what was asked»; лимит делегирования «delegate only for large independent tracks; do not use subagents to verify your own work; keep spawn counts low» + детерминированные капы `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` / `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` в `settings.json.env`; калибровка длины файлов «match length to what the task needs, no filler sections» (для PROGRESS/STATUS); секция «Compact instructions» (сохранять STOP-маркеры, выводы чеков, решения). **Убрать** из CLAUDE.md и промтов любые «verify with a subagent / double-check / re-verify» — на Opus 5 это даёт over-verification без выигрыша; строка D8 «показывай команду и вывод каждого чека» остаётся (это evidence для /goal-судьи, не просьба перепроверять). Evaluator (D7/D9) вызывается НЕ исполнителем самому себе, а отдельным финальным проходом из `/accept` (или как последний шаг предиката /goal) — паттерн generator/evaluator из harness-статьи, не self-verification. Нарратив Opus 5 длиннее — блок «одно предложение до первого tool call, апдейт только при важной находке, в конце — итог первым предложением». (3) `graphify claude install` → секцию из CLAUDE.md перенести в `.claude/rules/graphify.md` (`/doctor` вырезает выводимое из кодовой базы); `/context` после kickoff как гейт размера. (4) **`"autoMemoryEnabled": false`** в `kit/.claude/settings.json` — MEMORY.md (200 строк) грузится в каждую сессию, это скрытый второй закон против D10. (5) Хук PreToolUse-фильтр тестового вывода (официальный пример из docs/costs) с оговоркой: оставлять итоговую строку «N passed», иначе /goal-судья не увидит evidence. Effort и правки CLAUDE.md/settings — только на старте сессии (смена посреди инвалидирует prompt-cache); на Opus 5 думание включено по умолчанию и отключается только на effort ≤ high — не отключать, снижать effort; кэш час на подписке, 5 минут на usage credits.
